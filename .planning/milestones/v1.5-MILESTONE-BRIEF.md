## Original milestone definition (renumbered)

### 🚧 v1.5 Python Migration (In Progress)

**Milestone Goal:** Re-platform the `bin/` toolchain from Bash to Python — extract the logic already embedded in `python3` heredocs (~72% of `bin/`) into an installable package with a shared `common/` core, behind `bin/<name>.sh` exec-shims that preserve every CLI / CI / hook contract (shim-and-swap). A pure internal refactor: it relocates logic and adds no user-facing capability, so **behavior parity is the acceptance bar throughout**. Sequencing is load-bearing — the package skeleton, a *frozen* shared `common/`, and the instrumented-bash parity oracle (`WIKI_IMPL=bash|py`) are built FIRST (the one hard serialization point) so every subsequent port can be diffed byte-for-byte against a held-fixed bash oracle; then every cluster migrates **in parallel** behind that frozen surface (fan-out) and fans back in through a single cutover; the wholesale CLI→pytest conversion is the final, deferrable phase. The 3-phase shape (foundation → parallel migration + cutover → terminal conversion) deliberately exploits GSD's plans-in-waves parallelism: the conflict-avoidance work is front-loaded into Phase 24 so Phase 25's migration plans can run concurrently in isolated worktrees.

**Standing criteria (apply to every v1.5 phase, restated where load-bearing):**
- All existing CI gates (`lint`, `privacy-leak`, `strict`, `skills-check`, `neutrality`, `setup-parity`) stay green with their required-check names unchanged (PKG-04).
- Each migrated `bin/<name>.sh` stays a thin `exec`-shim preserving the exact argv / exit-code / stdout-vs-stderr contract; no downstream caller changes (PKG-03).
- `AGENTS.md ≡ CLAUDE.md` byte-equality (`sync-claude --check`), neutrality, and privacy gates remain green.
- Net-new pytest unit coverage (TEST-06) grows alongside each Wave-1 cluster (amortized), not deferred to one phase.

#### Phase 25: Parallel Migration + Cutover
**Goal**: Every in-scope script runs on Python behind its `.sh` shim, parity-green, and the migration is documented and verified — leaving only the deferrable Phase-24 pytest conversion. The phase is structured as a fan-out/fan-in over the frozen Phase-22 surface: independent cluster ports run concurrently (Wave 1), then a single cutover fans them in (Wave 2).
**Depends on**: Phase 24
**Requirements**: MIG-01, MIG-02, MIG-03, MIG-04, MIG-05, MIG-06, CUT-01, TEST-06
**Structure — TWO WAVES** (this drives `/gsd-plan-phase` decomposition):
  - **Wave 1 — parallel cluster ports.** Independent plans (≈5–6, finalized at plan-phase), each in its own git worktree, each gated by its own test suite under `WIKI_IMPL=py` byte-identical to `WIKI_IMPL=bash`, each reads-only on the frozen `common/`, each grows its own net-new pytest unit tests (TEST-06):
      - **brownfield** (consumes `common/`; the architectural template) — MIG-01
      - **lint + audit-claims TOGETHER** (the long pole; porting the pair is what retires the byte-copy) — MIG-02
      - **checkers** (`check-neutrality`, `check-privacy`, `check-sources-cloud-safe`) — MIG-03
      - **setup/release** (`init-wizard`, `gen-skills`, `release`, `sync-claude`) — MIG-04. Note: `init-wizard` is RECOMMENDED to be isolated as its own plan at plan-phase, since it is the riskiest port (interactive + `setup-parity` byte-equality).
      - **wiki-ops** (`ingest`, `validate-op`, `search`, `requirements-sync`, `pdf-extract`) — MIG-05, with MIG-06 retirements folded in (retire `migrate-privacy-dirs.sh`; leave `install-hooks.sh` as bash).
  - **Wave 2 — cutover fan-in.** One plan, depends on all of Wave 1 (CUT-01): author the migration decision record, verify every `bin/*.sh` reference across `schema/`, `docs/`, `CLAUDE.md`/`AGENTS.md`, `.claude/settings.local.json`, hold `AGENTS.md ≡ CLAUDE.md` byte-equality, and confirm all standing gates green on `WIKI_IMPL=py`.
**Success Criteria** (what must be TRUE):
  1. `WIKI_IMPL=py` produces byte-identical output to `WIKI_IMPL=bash` for every in-scope cluster across its suite, with the bash oracle held fixed (untouched).
  2. Hard compatibility contracts preserved: the `lint --ci --format json` schema/exit contract locked by a golden (consumed by `json-to-annotations.py`) + lint's dual-mode exit codes; the `audit-claims --verifier` STDIN-only / `shell=False` egress security contract verbatim; divergent exit codes (`sync-claude`=2, `init-wizard`=3, `gen-skills`=1, checkers=2); `setup-parity` wizard-vs-manual byte-equality + pre-commit hot-path latency; the `make_yaml` byte-exact chokepoint.
  3. Parallelism discipline holds: frozen `common/` + pre-declared entry points mean Wave-1 plans never write shared files; per-plan git-worktree isolation handles disjoint files; **ownership-rebase is the mid-wave fallback** if a `common/` gap surfaces (one plan lands the addition, others rebase + re-verify parity).
  4. `migrate-privacy-dirs.sh` retired and `install-hooks.sh` left as bash, both recorded; migration decision record authored; all `bin/*.sh` doc references verified accurate; `AGENTS.md ≡ CLAUDE.md` held.
  5. All in-scope scripts run on `WIKI_IMPL=py` with every standing CI gate green; net-new pytest unit coverage (TEST-06) is in place across all clusters.
