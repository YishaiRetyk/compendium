### Phase 0 — Privacy Architecture: per-page → asymmetric two-dir  *(foundational, GATES Phase A)* — COMMITTED

**This phase must land before Phase A extracts §13** — you cannot extract §13 to reference until
its new shape is decided, or you extract the wrong thing. It also removes the one safety rule that
otherwise had to stay resident (see "Knock-on" below).

**Decision (ACCEPTED 2026-06-04):** Replace the current **per-page** privacy model (§13: per-page
`privacy` field + three-level precedence + inheritance + fail-closed, with the cloud agent expected
to honor it every turn) with a **per-vault asymmetric two-directory** model.

Three options were weighed:
1. *Per-page mixed* (status quo) — max cross-tier synthesis + cloud-quality on safe pages, but heavy
   §13 machinery AND an **unscriptable** resident obligation: nothing can sit between the agent
   reading a `local_only` page and that turn going to the cloud API (the context window *is* the
   egress).
2. *Per-vault fully separate* — structural air-gap, ~zero machinery, but forbids cross-tier synthesis
   entirely and forces the weakest (local) model on *all* private content.
3. **Asymmetric two-dir (CHOSEN)** — one repo, two dirs (`wiki-cloud/`, `wiki-local/`), one unified
   Obsidian vault/graph, with **one-way permeability**: a *local*-model run may read both dirs (public
   content into a local model has no egress), so all cross-tier synthesis happens on the local side and
   lives in `wiki-local/`; a *cloud*-model run is **scoped to never read `wiki-local/`**.

**Why option 3:** it dominates the status quo on safety and simplicity while keeping the only synthesis
direction worth having (the forbidden direction, local→cloud, is exactly the leak). The boundary stops
being "a rule the cloud agent must remember" and becomes "a directory the cloud session physically
cannot open" — structural, config-enforced, scriptable.

**Enforcement (the point):** "cloud runs never read `wiki-local/`" is a **harness permission**
(a `deny`-read on `wiki-local/` in the cloud session's `settings.json`, or two clones opened in two
differently-configured sessions), NOT a resident agent rule. This is the automatic-gate tier — it
fires without the agent's memory.

**Migration is trivial for the creator vault:** it is currently single-tier (54/54 content pages
`cloud_safe`; the only two `local_only` files are `wiki/maintenance/audit-{report,state}.md`,
script-generated control-plane). Effectively: declare the vault `cloud_safe`, relocate the two audit
artifacts, done. The weight of this phase is template/schema/tooling, not data.

**Knock-on (re-tags the extraction map):** §13's resident obligation moves from *"stays resident
(clause-2b, unscriptable)"* to **"removed — enforced structurally."** The single irreducible safety
rule in the always-loaded core is dissolved into a setup-time structural fact + a harness permission,
so privacy leaves the core almost entirely. Phase A's handling of §13 changes from "extract the
per-page model verbatim" to "extract the *rewritten* asymmetric model."

  (`trigger_type: schema-update`) written *when this ships* — superseding the implicit per-page §13
  framing. (Not written now; produced at execution, per the uniform-piped-links precedent.)
- **REQ prefix:** `PRIV`

## Extraction Map — Inclusion-Test Disposition (what stays / what extracts)

> **This supersedes line-count targeting.** The core is not sized to a number; its contents are decided
> by an **inclusion test**, and the ~145-line total is an *output*, not a goal. Built section-by-section
> in the 2026-06-04 design review; itemized to exact line numbers against the live 1,689-line file.

**The inclusion test — a section/rule stays resident only if it is:**
1. **ambient** — applies on every turn with no natural just-in-time load point; OR
2. **unscriptable AND unacceptable-miss-cost** — a safety invariant no automatic gate can enforce and
   whose violation is irreversible (the only clear case, privacy-of-reasoning, is *dissolved* by Phase 0
   → so this clause is nearly empty post-Phase-0); OR
3. **dispatch** — needed to route to the right extracted file.

**Everything else extracts.** It has a clean JIT load point (you're authoring / ingesting / linting) and
an acceptable, gate-caught miss-cost. Rules that an automatic gate already enforces are demoted to a
one-line "enforced by `bin/…`, see ref." A line tripwire (not target) may fire a re-audit if the core
drifts upward and the test is being applied loosely.

## Design Constraints (Non-Negotiable — carry into every phase)

- **Markdown-authoritative.** Canonical behavior stays in plain markdown any harness can read.
  Claude Code is MVP runtime; Codex/Cursor/others are first-class future consumers.
- **Byte-equality preserved.** `AGENTS.md ≡ CLAUDE.md` via `.githooks/pre-commit` → `bin/sync-claude.sh --check`.
- **Wizard pipeline preserved.** `schema/AGENTS.template.md` → `bin/init-wizard.sh` still renders
  `AGENTS.md`; extracted `schema/reference|workflows/*.md` are copied wholesale (no new render logic).
- **Always-loaded safety core stays resident:** provenance requirement, MUST-NOT list (verbatim),
  write-back-mandatory, structured-op vocabulary. *No agent may start work and discover a safety rule
  on demand.* **Privacy is NO LONGER in this list** — Phase 0 converts it from a resident rule into a
  structural fact (directory + harness permission), which is the only safety invariant that was
  genuinely unscriptable under the per-page model. Inclusion is governed by the test "ambient /
  unacceptable-miss-cost-AND-unscriptable / dispatch," not by a line target.
- **CI gates unchanged in behavior.** `bin/lint.sh`, `bin/validate-op.sh`, `bin/check-privacy.sh`,
  `bin/check-neutrality.sh` operate on content, not file boundaries — extracted files must still pass
  (incl. neutrality + privacy-leak over the new `schema/reference|workflows/*.md`).
