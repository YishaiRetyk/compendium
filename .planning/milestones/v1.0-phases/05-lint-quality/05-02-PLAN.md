Create `bin/lint.sh` following the established CLI helper pattern (bash wrapper + inline python3 blocks). The script:

**Header and usage:**
```bash
#!/usr/bin/env bash
# bin/lint.sh -- Wiki health-check CLI helper (AGENTS.md section 11.3).
# Detects orphan pages, missing cross-references, stale claims, contradictions,
# knowledge gaps, and structural issues. Produces wiki/maintenance/lint-report.md.
#
# Zero LLM/API calls. Deterministic, file-based checks only.
# Requires: python3 with PyYAML.
set -euo pipefail
```

**Argument parsing:** Support these flags:
- `--help` / `-h`: Print usage and exit
- `--dry-run`: Report findings without applying auto-fixes or writing report page
- `--fix`: Apply mechanical auto-fixes (stale markers, has_contradictions sync). Default is report-only.
- `--category <cat>`: Run only specified category (orphan, crossref, stale, contradiction, gap, provenance, yaml). Default: all.
- First positional arg: wiki directory path (default: `wiki/`)

**Core architecture:** Use the finding accumulator pattern. Each check produces lines in format:
`severity|category|path|message`

All findings are accumulated into a temporary file. After ALL checks complete (even if some produce errors), the script proceeds to report generation and summary output.

**Exit code contract (addresses review concern about risky exit codes):**
- Exit 0: Script ran successfully (even if error-level FINDINGS exist)
- Exit 1: Script itself FAILED to run (python3 not found, wiki dir missing, IO error)
- Rationale: Lint findings are expected output, not process failures. Breaking automation because the wiki has a broken provenance ref defeats the purpose.

**Implement these checks in this task:**

1. **YAML frontmatter validation** -- Use inline python3 with PyYAML. For each .md file in wiki/ (excluding index.md, log.md, maintenance/):
   - Parse YAML frontmatter between `---` delimiters using `yaml.safe_load()`
   - Check all base fields present (id, title, type, status, summary, created_at, updated_at, sources, epistemic_status, tags, domains, supersedes, superseded_by, privacy, aliases, has_contradictions, knowledge_domain)
   - Validate enum fields: type in (entity, concept, source, comparison, overview), status in (active, stale, superseded, archived), epistemic_status in (sourced, mixed, tentative, stale), privacy in (local_only, cloud_safe)
   - For type: source pages, check additional fields: path, content_hash, ingested_at, source_type, compilation_status
   - Severity: error for parse failures or missing required fields

2. **Provenance validation** -- Use inline python3 with regex `\[prov:([^#\]]+)#([^|\]]+)(?:\|([^|\]]+))?(?:\|([^\]]+))?\]`:
   - Extract all `[prov:]` references from page bodies
   - Build source registry from `wiki/sources/*.md` frontmatter `id` fields
   - Flag references to source IDs not found in registry
   - Severity: error for broken refs

3. **Orphan detection** -- Use inline python3:
   - Build resolution map: for each wiki page, collect id, title, and aliases. Store all variants in **lowercase** for case-insensitive matching (addresses Gemini wikilink resolution concern)
   - Extract all wikilinks from all page bodies using regex `\[\[([^\]|]+)(?:\|[^\]]+)?\]\]`, normalize to lowercase for matching
   - A page is orphan if NO other page's wikilinks resolve to its id, title, or any alias (case-insensitive)
   - Exclude index.md, log.md, lint-report.md from orphan candidates
   - Severity: warning

4. **Missing cross-references** -- Use inline python3:
   - For each pair of active pages (status not archived/superseded): if they share 2+ values in `domains` list AND 2+ values in `tags` list, AND they lack mutual wikilinks (case-insensitive resolution), flag as missing cross-reference
   - Severity: warning
   - Report-only (no auto-fix per revised AGENTS.md section 11.3)

**Finding accumulator and stdout summary:**
After all checks, sort findings by severity (error first, then warning, then info). Print compact stdout summary to stderr so it doesn't interfere with piping:

```
=== Wiki Lint Results ===
Errors:   N
Warnings: N
Info:     N
~~~~~~~~~~~~~~~~~~~~~~~~

  [error] path: message

Auto-fixes applied: N (or "none -- use --fix to apply")

```

Print "Linting [path]..." progress lines to stderr for user feedback during runs.

**Important implementation details:**
- All python3 code runs as inline heredoc blocks (python3 << 'PYEOF' ... PYEOF)
- The python3 block receives the wiki directory path and flags as arguments
- Findings are accumulated in a temp file (mktemp), cleaned up on exit via trap
- Use a single comprehensive python3 block for all checks (more efficient than multiple invocations)
- The script must work with the current wiki (10+ pages across 5 directories)

**Add staleness detection to bin/lint.sh's python3 block:**

Implement the staleness check as a new function in the existing python3 inline block:

1. **Hash override check** (per D-09): For each source page in `wiki/sources/`, compare `content_hash` vs `compiled_against_hash`. If they differ AND `compilation_status` is not `stale`, flag all claims linked to that source (via `[prov:source_id#...]`) as stale. Severity: warning, category: stale.

2. **Decay rate check** (per D-07, D-08, D-10):
   - For each wiki page (non-source), read `knowledge_domain` from frontmatter
   - Look up base decay period from table: software=180, science=730, biography=1825, personal-goals=90, default=365
   - For each `[prov:]` marker on the page, extract the `checked_at` date (4th field). If missing, fall back to: source page's `ingested_at`, then wiki page's `updated_at`
   - Read the claim's `[epistemic:: status]` if present on the same line, look up modifier: sourced=1.0, mixed=0.85, inferred=0.75, tentative=0.5
   - Compute effective_decay = base_days * modifier
   - If `(today - checked_at_date).days > effective_decay`, the claim is stale
   - Severity: warning, category: stale

3. **Auto-fix stale markers** (only when `--fix` flag is passed, per revised staleness auto-fix rules in AGENTS.md):
   
   **Claim boundary definition:** A "claim" is a single line (bullet point or paragraph line) that contains one or more `[prov:...]` markers.
   
   **Marker placement rules:**
   - Place `[epistemic:: stale]` immediately after the last `[prov:...]` marker on the claim line
   - If the claim line already contains `[epistemic:: sourced]`, `[epistemic:: inferred]`, or `[epistemic:: mixed]`, REPLACE that marker with `[epistemic:: stale]` using string substitution
   - If the claim line already contains `[epistemic:: stale]`, do NOT add a duplicate -- skip this claim
   - Do NOT modify lines that have no `[prov:]` markers
   
   **Idempotency:** Running `--fix` twice on the same file produces the same result. The second run finds no new stale claims to fix because they already have `[epistemic:: stale]`.
   
   **File writing:** Read the entire file into memory, make all substitutions, write back only if changes were made. Track which files were modified and which claims were updated.
   
   - Add auto-fix entries to findings: `info|autofix|path|Added [epistemic:: stale] to claim at line N`
