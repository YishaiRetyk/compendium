**Output Contract (addresses review concern: deterministic output format):**

Each mode has a defined, machine-parseable output format:

**Default mode (index search):**
```
=== Search Results ===
wiki/entities/daniel-kahneman.md -- Nobel laureate psychologist known for prospect theory
wiki/concepts/prospect-theory.md -- Descriptive theory of decision-making under risk
=== N result(s) ===
```
One line per result. Format: `<path> -- <TL;DR first line>`. Lines always start with `wiki/`. The footer line is `=== N result(s) ===` where N is the integer count.

**--paths-only mode:**
```
wiki/entities/daniel-kahneman.md
wiki/concepts/prospect-theory.md
```
Bare file paths, one per line. No headers, no footers. Suitable for piping to `xargs` or `while read`.

**--query mode:**
```
=== Query Prompt ===

Question: <the user's question>

Relevant wiki pages (read in this order, TL;DR first, drill into Detail only if needed):

1. <path> -- <TL;DR>
2. <path> -- <TL;DR>

Instructions:
- Read TL;DR and Key Facts sections first (progressive disclosure).
- Read Detail sections only where shallow content is insufficient.
- Cite specific wiki pages and provenance markers in your answer.
- If the answer produces novel synthesis, write it back to the wiki per AGENTS.md section 11.2.
=== End Query Prompt ===
```

**No results (any mode):**
```
No results found for "<keyword>"
```
Exits 0 (no results is not an error).

**Error conditions:**
- No arguments: print usage to stderr, exit 1
- Missing wiki/index.md: `"ERROR: wiki/index.md not found"` to stderr, exit 1
- Invalid flag: `"ERROR: Unknown option: <flag>"` to stderr, exit 1

**Default mode (per D-13):** Parse `wiki/index.md` for keyword matches (case-insensitive grep on index lines matching `^\- \[\[`). For each match, extract the page path from the wikilink title, find the corresponding file in `wiki/` subdirectories, and extract the TL;DR (first non-empty line after `## TL;DR`). Print in the format above.

When `--fulltext` is passed, ALSO run `grep -ril "$keyword" wiki/` (excluding index.md and log.md) and add any results not already found via index. Extract TL;DR for those too.

**`--paths-only` mode (per D-15):** Same search logic but print only file paths, one per line. No TL;DR extraction, no headers/footers.

**`--query` mode (per D-14):** Takes a natural language question. Searches index for relevant pages (split question into words longer than 3 chars, search each). Emits the query prompt in the exact format documented above.

**Helper functions:**

`extract_tldr()`:
```bash
extract_tldr() {
    local file="$1"
    sed -n '/^## TL;DR/,/^## /{/^## TL;DR/d;/^## /d;/^$/d;p;}' "$file" | head -1
}
```

`resolve_page_path()` -- Given a page title from the index (e.g., "Daniel Kahneman"), find the corresponding file by converting title to kebab-case and checking wiki/ subdirectories:
```bash
resolve_page_path() {
    local title="$1"
    local slug
    slug=$(echo "$title" | tr '[:upper:]' '[:lower:]' | sed -E 's/[^a-z0-9]+/-/g; s/^-+|-+$//g')
    for dir in wiki/entities wiki/concepts wiki/sources wiki/comparisons wiki/overviews; do
        if [ -f "$dir/$slug.md" ]; then
            echo "$dir/$slug.md"
            return 0
        fi
    done
    # Fallback: grep for matching title in all wiki files
    grep -rl "^title:.*$title" wiki/ 2>/dev/null | head -1
}
```

**Exit codes:** 0 = results found or no results (informational), 1 = error (bad args, missing index).
