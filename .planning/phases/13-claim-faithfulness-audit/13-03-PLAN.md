<objective>
Land the genuinely-new 20% of the audit and the load-bearing FAITH-04 boundary: the §13 privacy resolver (`bin/lib/privacy_resolve.py` — no such resolver exists in-repo today; `check-privacy.sh` is only a leak-grep) and the verdict/verifier dispatch in `bin/audit-claims.sh` that overwrites Plan 02's declared-enum `insufficient` ("verifier not run") stub with the real dispatched verdict. This plan carries the **primary threat model for the phase**: a `local_only` claim or passage leaking to a cloud verifier is the central security threat (D-02), and the mitigation is the mechanically-enforced fail-closed worklist partition proven by a recording-verifier negative test.

The deterministic core (Plan 02) sends nothing anywhere. This plan adds the egress surfaces — the verdict dispatch AND `--emit-worklist` — behind a SINGLE partition point, and guarantees `local_only` claims/passages are partitioned out of BOTH before any cloud command runs or any worklist is printed. **The partition gates on the EFFECTIVE claim privacy — the strictest of {claim-page privacy, source-summary privacy, raw-source privacy, enclosing-dir signal, fail-closed default} — NOT source privacy alone.** Four cross-AI review HIGH concerns (two from each cycle) are closed here:
- **(Cycle-1 HIGH-1)** verifier locality is made explicit-only — every `--verifier` is cloud/egress by default and `local_only` admission requires an explicit `--allow-local` (with `--local-verifier` as sugar), so no command is ever implicitly trusted.
- **(Cycle-1 HIGH-2)** the privacy partition is applied BEFORE worklist emission, not only before subprocess dispatch, so `--emit-worklist` cannot become an accidental egress surface for a cloud operating agent.
- **(Cycle-2 HIGH-A — NEW)** the partition resolves the EFFECTIVE claim privacy via `resolve_effective_claim_privacy(page_fm, page_path, source_fm, raw_source_fm, source_path)`, folding the wiki page's OWN `privacy` frontmatter (and the raw-source frontmatter) into the §13 stricter-wins computation. A `privacy: local_only` page citing a `cloud_safe` source now has its CLAIM text withheld — FAITH-04 governs local_only *claims*, not only local_only source passages. (REVIEW MEDIUM "raw-source frontmatter ignored" is subsumed by this fix.)
- **(Cycle-2 HIGH-B — NEW)** is closed in Plan 02 (the generated `audit-report.md` / `audit-state.md` default to `privacy: local_only`); this plan keeps the partition the single chokepoint that feeds those artifacts safely.

Purpose: close FAITH-04 mechanically for *claims* (not just source passages, and not as a documented promise) and complete FAITH-02's judgment half via the pluggable verifier.
Output: `bin/lib/privacy_resolve.py` (source-privacy resolver + the strictest-wins effective-claim resolver), the privacy-chokepoint + verdict-dispatch additions to `bin/audit-claims.sh`, and the privacy/verdict/verifier `test_*.sh` files including the load-bearing `test_privacy_partition_fail_closed.sh`, the worklist-egress twin `test_emit_worklist_partition.sh`, the explicit-locality `test_local_verifier_alias.sh`, the new `test_claim_page_privacy.sh` (local-only page + cloud-safe source) and `test_raw_source_privacy.sh` (cloud-safe page/summary + local-only raw source), and the `shlex` correctness `test_verifier_with_args.sh`.
