def resolve_source_privacy(source_fm, source_path):
    fm_priv = (source_fm or {}).get('privacy')
    explicit = fm_priv if fm_priv in ('local_only', 'cloud_safe') else None
    dir_priv = None

        dir_priv = 'local_only'

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| audit pipeline → verdict dispatch (`--verifier <cmd>` / agent) | THE sole egress point — the only place wiki/source content leaves the deterministic core. The entire FAITH-04 design exists to control this boundary |
| `local_only` source passage → cloud verifier | The load-bearing threat: a private passage must never cross into a cloud command |
| operator-supplied `--verifier <cmd>` → subprocess | A trusted-by-construction operator command; the risk is the audit injecting claim/passage text into its argv |
| `--verifier` stdout → finding parser | Untrusted/possibly-malformed output crossing back into the audit |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-08 | Information Disclosure | `local_only` passage leaks to a cloud verifier (FAITH-04 raison d'être) | mitigate | Fail-closed §13 resolution (`bin/lib/privacy_resolve.py`, unknown→local_only) + mechanical worklist partition (D-02): `local_only` is WITHHELD from the dispatched set unless `--allow-local`. Evidence: `test_privacy_partition_fail_closed.sh` asserts the recording verifier's sentinel log never contains the local_only passage text — enforcement, not a promise |
| T-13-09 | Elevation of Privilege | command injection via claim/passage interpolated into `--verifier` argv | mitigate | Payload passed via `subprocess.run(..., input=json, text=True)` STDIN ONLY; claim/passage never appear in argv. `test_verifier_contract.sh` round-trips stdin; acceptance grep forbids subprocess argv built from claim/passage |
| T-13-10 | Tampering / DoS | malformed or malicious `--verifier` stdout | mitigate | `try: json.loads(out)` with except → emit an `insufficient`-style finding noting unparseable verifier output; NEVER `eval`; never crash. `test_verifier_contract.sh` asserts a malformed verifier yields a finding and exit 0 |
| T-13-11 | Spoofing | a finding's verdict not traceable to its claim | accept | Findings carry source_id + locator + line + path (the 9-key dict); `--apply-verdicts` keys on these four to bind a verdict to its claim — sufficient for a review-only diagnostic |
