<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source page `path:` field → filesystem open() | The `path:` value is read from an in-repo source page and used to open a raw file; a crafted `..`-escaping path could read outside the repo |
| raw source text → finding output | Raw passage text flows into the report/JSON; in this plan it never egresses to any verifier (verdict is a stub) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-04 | Tampering | path traversal via crafted `path:` | mitigate | Resolve `path:` under `repo_root` with `os.path.realpath`/normalize; reject any path escaping the repo root → skip the claim with an `insufficient-locator`-style note, never open it (13-RESEARCH.md Security Domain) |
| T-13-05 | Information Disclosure | feeding whole document when `#p` cannot bound | mitigate | `insufficient-locator` is first-class — when `<!-- page: N -->` markers are absent, return None and NEVER pass >1 section to any downstream step (Pitfall 2); enforced by `test_resolve_p_unmarked.sh` |
| T-13-06 | Tampering | circular verification (audit the wiki against itself) | mitigate | resolve_locator opens the RAW file at `path:`, never the summary body; `test_no_circular_verify.sh` asserts the resolved passage matches raw-file text, not the divergent `## Extracted Claims` text (D-11, highest-severity pitfall) |
| T-13-07 | Tampering | scope creep into wiki page mutation | mitigate | The script writes ONLY to `wiki/maintenance/audit-report.md` and `audit-state.md`; `test_no_page_mutation.sh` asserts `git status` of wiki/{entities,concepts,...} is unchanged after a run (SC-5) |
</threat_model>
