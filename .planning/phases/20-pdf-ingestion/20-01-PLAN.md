<objective>
Build the PDF→Markdown acquisition glue script `bin/pdf-extract.sh` and stand up the Phase 20 test harness. This is the tooling half of PDF-01 and the first repo script to invoke a local model.

Purpose: Acquisition is the one dimension PDF changes (D-05). The marker grammar already exists in `schema/reference/provenance.md`; this script PRODUCES markers, it does not redefine them.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → pdf-extract.sh | Untrusted PDF file path + filename supplied as a positional arg |
| pdf-extract.sh → local Ollama HTTP | base64 image payload POSTed to localhost:11434 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01 | Tampering/Injection | `bin/pdf-extract.sh` PDF path arg | mitigate | All file paths are passed as quoted shell variables ("$PDF", "$OUT", "$PNG"); jq -n with --arg performs the JSON escaping for the base64 payload + prompt (no string-concatenated JSON). No `eval`, no unquoted expansion. |
| T-20-02 | Information Disclosure | Ollama HTTP call | accept | Endpoint is localhost-only (default http://localhost:11434); no network egress beyond the local model server; no secrets in the request. Low-value, local-only target. |
| T-20-03 | Denial of Service | per-page model calls on a huge PDF | accept | Validation artifact is scoped to ~5-30 pages (D-12); the script processes pages serially and is operator-invoked, not a service. Out of scope to add rate limiting. |
| T-20-04 | Spoofing | unreachable/wrong Ollama server | mitigate | Preflight `curl -sf $OLLAMA_URL/api/tags` probe fails loud with a clear error before any page is rendered, rather than silently producing empty `.response` markers. |
</threat_model>
