## Decisions Made

- **No usage error for `--staged` without `--strict`.** Per CONTEXT.md "Claude's Discretion", chose the silent no-op contract (D-05) over an explicit error/usage hint. Implemented naturally: STAGED_MODE only takes effect inside `strict_check()`, which itself is gated by `if not STRICT_MODE: return`. Simpler, more composable, matches the "auto-detect by chain context" idiom of `--ci` / `--count-skips`.
- **No --skip-category bypass for the staged path.** The plan said the hook can run `bash bin/lint.sh --strict --staged --category provenance`. Because STAGED_MODE branches first AND returns immediately, the D-08 DR-match block is never reached; the `--category provenance` filter is effectively a no-op for staged invocations. This eliminates the silent dependency on category filtering that WARNING 3 flagged.
- **PR-mode message preserved verbatim, staged-mode gets the longer message.** Per WARNING 4: Phase-09 tests may grep against the original concise message `f"new {t} page has zero [prov:...] markers (D-10)"`. The new D-08 actionable-paths UX is mode-gated to staged-mode only, so `tests/phase-09/test_lint_strict_new_page.sh` still passes without modification.
- **bootstrap_date in fixture frontmatter required no special handling.** PyYAML safe_load parses ISO 8601 dates as `datetime.date` objects natively; the gate's only frontmatter reads (`fm.get('type')`, `fm.get('example')`, `fm.get('bootstrap_stage')`) are unaffected.
