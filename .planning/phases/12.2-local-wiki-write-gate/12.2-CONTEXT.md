# Phase 12.2: Local Wiki Write Gate - Context

**Gathered:** 2026-05-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Add a deterministic, staged-index-aware pre-commit gate that catches new synthesized wiki pages without `[prov:...]` markers before they land in local history. The gate reuses `bin/lint.sh --strict` semantics (D-10 only) by adding a new `--staged` mode to `bin/lint.sh` rather than inventing a parallel policy surface. Compose with — not replace — the existing AGENTS.md ↔ CLAUDE.md sync hook. Trunk-based dev (`branching_strategy: none`) means the local commit path is the only enforcement point that fires before code lands; CI's `--strict` is post-fact.

**In scope:** new `--staged` flag on `bin/lint.sh`; one-line extension to `.githooks/pre-commit`; documentation amendments to AGENTS.md §11.3, docs/reference/ci.md, CONTRIBUTING.md; tests under `tests/phase-12.2/`; flip WGATE-01..04 in REQUIREMENTS.md; `12.2-VERIFICATION.md` artifact.

**Out of scope (per ROADMAP non-goals):** semantic claim-faithfulness checking (Phase 13); cloud API use; auto-rewrite of pages; full-vault lint on every commit; D-08 staged enforcement (DR-match for added epistemic claims) — stays CI-only; new policy surface separate from `bin/lint.sh`.

</domain>

<decisions>
## Implementation Decisions

### Gate implementation surface
- **D-01:** Extend `bin/lint.sh` with a new `--staged` flag (orthogonal to `--strict`). Single policy surface (SC3). Adds ~60–100 lines wrapping existing `strict_new_pages()` / `strict_added_epistemic_claims()`. Rejected: a separate `bin/wgate.sh` wrapper (would invent a parallel policy surface and silently lag if `PROVENANCE_REQUIRED_TYPES` drifts in lint); inline check in `.githooks/pre-commit` (duplicates frontmatter parsing, no test harness).
- **D-02:** `--staged` swaps the diff source. Where the existing `strict_new_pages()` calls `git diff --name-status origin/main...HEAD`, the staged path calls `git diff --cached --name-only --diff-filter=A`. The PR-mode path is unchanged. WGATE-03 is satisfied: staged-mode does not rely on `origin/main...HEAD` semantics; PR-mode and staged-mode are explicitly distinct code paths.
- **D-03:** `--staged` reads files from the **working tree**, not from staged blobs (`git show :<path>`). Pre-commit hooks fire after `git add`, so working-tree content matches the index for staged paths in the typical flow. Documented assumption: "the gate verifies what you staged, expecting working-tree content to match the index." If a user does `git add foo.md && echo extra >> foo.md && git commit`, the gate sees the dirty version (which already includes the staged content) — that's a known caveat, not a bug.
- **D-04:** `--staged` implements **D-10 only** (new-page provenance under `wiki/{entities,concepts,overviews,comparisons}/`). D-08 (added `[epistemic:: inferred|tentative]` claims need a matching DR) stays CI-only via the existing `--strict` PR-diff path. WGATE-02 mandates D-10; D-08 staged enforcement is explicitly deferred to a future phase if local quality regressions surface.
- **D-05:** Hook invocation: `bash bin/lint.sh --strict --staged --category provenance --format text`. `--staged` is a no-op without `--strict` (or short-errors with a usage hint) — it exists to scope strict checks to the index.
- **D-06:** Exit policy reuses `--strict`'s contract: exit 1 iff any post-remap error-severity finding exists. `provenance` already remaps to `error` in `CI_SEVERITY_REMAP`. No new exit-code dialect (exit 2 would conflate WGATE with public-paths leak gates; exit 3 introduces a new convention).

### Hook composition
- **D-07:** Single `.githooks/pre-commit` script. Order is **sync-claude first, then write-gate**. sync-claude can mutate the staging area (it runs `git add CLAUDE.md` on drift) so it must run first; otherwise the write-gate snapshots a state that's about to change. Existing sync-claude logic is preserved unchanged (SC6 / WGATE-04).
- **D-08:** Failure UX = lint.sh's existing `add_finding` text + a single hook footer line. Lint prints (e.g.) `error/provenance/wiki/concepts/foo.md: new concept page has zero [prov:...] markers (D-10)`. Hook appends one trailing line: `Write-gate failed. Add [prov:source_id#locator] markers to the page, set type: source / type: decision in frontmatter if it's not a synthesized page, or run `git commit --no-verify` to bypass.` Reuses Phase 9-02 output format (SC5 actionable).
- **D-09:** Bypass mechanism is **only `git commit --no-verify`** (per AGENTS.md §3 / CLAUDE.md §3 already-codified policy). No `WGATE_SKIP=1` env var. No per-page `wgate_exempt: true` frontmatter (would create a permanent bypass surface defeating the gate's purpose).
- **D-10:** `bin/install-hooks.sh` is **unchanged**. Hooks remain explicit-opt-in via `bash bin/install-hooks.sh` setting `core.hooksPath=.githooks`. Document activation in docs/reference/ci.md and CONTRIBUTING.md.

### Exemptions and brownfield
- **D-11:** Exempt pages with `bootstrap_stage: bootstrapped` in frontmatter from the provenance gate. Mirror lint.sh's existing line-885 special-case precedent. Rationale: brownfield-imported pages haven't been provenance-bootstrapped yet — that's what `bin/brownfield.sh suggest` + migration `02-provenance-bootstrap.sh` exists to do. A user mid-onboarding (post-`bin/brownfield.sh bootstrap`, pre-migration-02) can commit the bootstrapped result without false-blocks (SC4 / WGATE-04).
- **D-12:** Pages with `bootstrap_stage: verified` are **NOT** exempt — they've been promoted through the 5-gate `verify --promote` flow and are first-class wiki content from the gate's perspective. Greenfield pages have no `bootstrap_stage` field at all and are gated normally.
- **D-13:** Frontmatter parsing reuses lint.sh's existing `parse_fm_from_text()`. Single parser surface; consistent failure modes across all lint paths (rejected: ad-hoc grep for `^type:` / `^bootstrap_stage:` — brittle on edge cases).
- **D-14:** `examples/` paths are skipped at the path-prefix layer **before** any frontmatter is read. Matches lint.sh `EXCLUDE_DIRS = {maintenance, examples}` precedent. Only paths matching `wiki/(entities|concepts|overviews|comparisons)/.*\.md` reach the provenance check at all. The `example: true` frontmatter field is honored secondarily (per AGENTS.md §5 it can apply anywhere) but in practice the path filter handles all v1.1 cases.
- **D-15:** Exemption set, ordered: (1) path not under `wiki/(entities|concepts|overviews|comparisons)/`; (2) path under `examples/` (anywhere in the tree); (3) frontmatter `type: source`; (4) frontmatter `type: decision`; (5) frontmatter `example: true`; (6) frontmatter `bootstrap_stage: bootstrapped`. If any of these match, the page is not gated. The `bootstrap_stage: verified` value is **not** an exemption.

### Documentation surface
- **D-16:** AGENTS.md §11.3 (CI mode block) is the **normative source of truth** for `--staged` semantics, exemptions, exit codes, and bypass. Phase 9-06 already established §11.3 as canonical for `--strict` / `--ci`; `--staged` plugs into the same section. Add a new flag row to the §11.3 table; add a "Staged-mode rules" subsection covering: (a) what triggers the gate, (b) exemption set (D-15), (c) bypass (`--no-verify`), (d) `--staged` requires `--strict`.
- **D-17:** `docs/reference/ci.md` and `CONTRIBUTING.md` get **operational** sections (how to install hooks, how to bypass, how to fix a blocked commit) that **link to AGENTS.md §11.3** rather than restate the rules. Mirrors the Phase 9-06 contract (rule rows in ci.md open with source-of-truth blockquotes pointing at §11.3).
- **D-18:** `schema/AGENTS.template.md` mirrors AGENTS.md for the §11.3 changes (TMPL-10 / D-03 byte-equality is enforced by the existing pre-commit sync-claude check; the canonical-AGENTS.md byte-equality fixture from Phase 11-05 will need a regenerate after the §11.3 amendment).

### Test surface
- **D-19:** Tests live under `tests/phase-12.2/` mirroring Phase 09's pattern: `run.sh` aggregator + `lib.sh` helpers + per-scenario `test_*.sh`. **Reuse `tests/phase-09/lib.sh`** helpers where applicable (`make_fixture_repo`, `setup_git_author`) by either sourcing the Phase-09 lib directly or by symlinking common helpers into a shared `tests/lib/` (planner's call — both are precedented by other phase test surfaces). The fixture-repo pattern (throwaway git init at test time via `mktemp`) is the right shape; staged-mode does not need `seed_origin_main_ref` (D-08-staged was deferred).
- **D-20:** Required test scenarios (planner can extend, must include at minimum):
  1. Greenfield `wiki/concepts/foo.md` with zero `[prov:]`, status A → exit 1 (gate blocks).
  2. Greenfield `wiki/concepts/foo.md` with at least one `[prov:]`, status A → exit 0.
  3. Modified existing `wiki/concepts/foo.md` (status M, not A) without `[prov:]` → exit 0 (only status-A pages gate).
  4. New `wiki/sources/foo.md` with `type: source` and zero `[prov:]` → exit 0 (exempt by type).
  5. New `wiki/decisions/dr-X.md` with `type: decision` → exit 0 (exempt by type).
  6. New page under `examples/kahneman/concepts/foo.md` with zero `[prov:]` → exit 0 (path-prefix skip).
  7. New `wiki/concepts/foo.md` with `bootstrap_stage: bootstrapped` and zero `[prov:]` → exit 0 (brownfield exempt).
  8. New `wiki/concepts/foo.md` with `bootstrap_stage: verified` and zero `[prov:]` → exit 1 (verified is NOT exempt).
  9. Hook ordering: pre-commit with sync-claude drift + a blocked write-gate page → sync-claude resyncs first, exits 1; rerun without drift → write-gate fires, exits 1 with footer; fix provenance → exit 0.
  10. `--no-verify` smoke: a blocked commit with `--no-verify` succeeds (sanity check — git's flag, not our code, but documents the contract).

### REQUIREMENTS.md / VERIFICATION.md cadence
- **D-21:** Flip WGATE-01..04 in REQUIREMENTS.md to `Complete` only after `12.2-VERIFICATION.md` is written. Use the Phase 7 / Phase 12.1 `bin/requirements-sync.sh --strict --phase 12.2` exit-0 contract as the green-light gate (acceptance criterion for the verification phase).
- **D-22:** `12.2-VERIFICATION.md` follows the Phase 7 mirror format (REQ-IDs in `## REQ-IDs Closed by This Phase` with file-path evidence per requirement). Each WGATE-0X row cites the specific test(s), AGENTS.md §11.3 line range, and `.githooks/pre-commit` evidence.

### Claude's Discretion
- Exact wording of the AGENTS.md §11.3 `--staged` subsection — D-15 fixes the **semantic content** (the exemption ordering and which fields trigger which behavior); cadence and prose style are open.
- Exact wording of the `.githooks/pre-commit` footer line (per D-08) — must mention the three actionable paths (add `[prov:]`, set type: source/decision, `--no-verify`); phrasing is open.
- Whether `--staged` lives in a new helper function or is woven into existing `strict_check()` via a base-ref / diff-source parameter — implementation pattern is the planner's call. The decision is "single policy surface"; the function decomposition is downstream.
- Whether to source `tests/phase-09/lib.sh` directly or extract shared helpers to `tests/lib/`. Phase 09.1 left the lib decomposition unsettled; Phase 12.2 may extract or may stay coupled — planner's call.
- Whether `bin/install-hooks.sh` gets a print-friendly note about the new gate (e.g., "Hooks installed: AGENTS↔CLAUDE sync + write-gate active") or stays silent. Cosmetic; not contract.
