    Write the following sections:

    **Section 1: Overview and Principles** (~30 lines)
    - State that this is the sole authoritative schema for the LLM Wiki Compiler
    - Three layers: raw sources (immutable), wiki (LLM-maintained), schema (this file + templates)
    - Core principle: the wiki is a persistent, compounding artifact
    - The LLM writes and maintains the wiki; the human curates sources and asks questions
    - List the four operations: ingest, query, lint, reflect
    - State that workflows are defined later in this document (Section 11)

    **Section 2: Directory Structure** (~50 lines)
    Per D-05, D-06, D-07, D-08, D-09:
    - Show the exact directory tree (copy from research Architecture Patterns section)
    - Explain `sources/` uses chronological nesting: `YYYY/YYYY-MM/YYYY-MM-DD-slug/`
    - Bundle folders when assets exist: `source.md` + attachments co-located
    - Single `.md` file for text-only sources (no bundle directory needed)
    - `wiki/` organized by page type: entities/, concepts/, sources/, comparisons/, overviews/
    - `wiki/index.md` and `wiki/log.md` live inside wiki/ (per D-07)
    - `schema/` is optional, for templates and examples
    - Source metadata (type, topic, privacy) stored in frontmatter, not directory structure (per D-09)

    **Section 3: Global Rules** (~40 lines)
    - All dates use ISO 8601 format: `YYYY-MM-DD` or `YYYY-MM-DDTHH:mm:ss`
    - All frontmatter field names use `snake_case` (Dataview compatibility per research Pitfall 2)
    - Commit conventions (per D-25, D-26): conventional commit format with types `ingest(source-slug):`, `query(topic):`, `lint(scope):`, `reflect(scope):`, `schema:`
    - One commit per logical operation, not per file
    - LLM navigation rule: always read `wiki/index.md` first, then drill into specific pages. Read shallow sections (TL;DR, Key Facts) before Detail sections. (per PROG-03)
    - Red links are allowed and intentional -- they signal knowledge gaps for the lint workflow (per D-33)

    **Section 4: Page Types and Templates** (~80 lines)
    Per D-06, SCHM-03, D-20 through D-24:
    Define five page types with their purpose and when to use each:

    1. **Entity** (`type: entity`) -- People, tools, organizations, specific named things
       Sections: TL;DR -> Key Facts -> Detail -> Related Pages -> Sources (per D-20)

    2. **Concept** (`type: concept`) -- Ideas, theories, frameworks, abstract topics
       Sections: TL;DR -> Key Facts -> Detail -> Related Pages -> Sources (per D-20)

    3. **Source Summary** (`type: source`) -- One per ingested source document
       Sections: TL;DR -> Key Takeaways -> Extracted Claims -> Notes -> Source Metadata (per D-21)
       Additional frontmatter: `path`, `url`, `content_hash`, `ingested_at`, `source_type`

    4. **Comparison** (`type: comparison`) -- Contrasting sources, viewpoints, or approaches
       Sections: TL;DR -> Bottom Line -> Comparison Table -> Detailed Comparison -> Sources (per D-22)

    5. **Overview** (`type: overview`) -- High-level topic summaries, synthesis pages
       Sections: TL;DR -> Key Facts -> Detail -> Related Pages -> Sources (same as entity/concept)

    For each type, include a brief example showing the section headings as `## Heading` markdown.

    **Section 5: Frontmatter Schema** (~80 lines)
    Per D-10, D-11, D-12, SCHM-04, OBSD-02:

    Define the base frontmatter fields required on EVERY wiki page:
    ```yaml
    ---
    id: slug-style-identifier        # Unique page ID, kebab-case
    title: "Human Readable Title"     # Canonical page title
    type: entity|concept|source|comparison|overview
    status: active|stale|superseded|archived
    summary: "One-sentence description for index scanning."
    created_at: YYYY-MM-DD           # ISO 8601
    updated_at: YYYY-MM-DD           # ISO 8601
    sources:                          # List of source IDs (strings, NOT wikilinks)
      - src-YYYY-MM-DD-slug
    epistemic_status: sourced|mixed|tentative|stale
    tags:                             # Flat list for Dataview queries
      - tag-name
    domains:                          # Topic/category classification
      - domain-name
    supersedes:                       # ID of page this replaces (if any)
    superseded_by:                    # ID of page that replaces this (if any)
    privacy: local_only|cloud_safe    # Privacy routing tier
    aliases:                          # Alternative names for Obsidian resolution
      - Alternate Name
    ---
    ```

    Explain each field's purpose and constraints. Note:
    - `sources` contains string IDs, NOT wikilinks (per research Pattern 3: Body Links, Frontmatter IDs)
    - `epistemic_status` values: `sourced` (directly from source), `mixed` (some sourced + some inferred), `tentative` (weak evidence), `stale` (likely outdated) (per D-11)
    - No `confidence` field -- epistemic_status is sufficient (per D-11)
    - Type-specific fields (provenance blobs, decay settings, comparison dimensions) go in type-specific sections, not base frontmatter (per D-12)

    Define type-specific additional fields for source summary pages:
    ```yaml
    path: sources/YYYY/YYYY-MM/YYYY-MM-DD-slug/source.md
    url: "https://..."                 # Original URL if applicable
    content_hash: "sha256:abc123..."   # For staleness detection
    ingested_at: YYYY-MM-DD           # When source was processed
    source_type: article|paper|transcript|journal|data|image
    ```

    **Section 6: Provenance, Epistemics, and Staleness** (~70 lines)
    Per D-13 through D-18, OBSD-01:

    Define inline provenance syntax:
    - Basic: `[prov:<source_id>#<locator>]`
    - Extended: `[prov:<source_id>#<locator>|<support_type>|<checked_at>]`

    Locator types (per D-14):
    - `#p12-14` -- page range
    - `#sec:introduction` -- section name
    - `#para3` -- paragraph number
    - `#t00:12:10-00:12:48` -- timestamp range (for transcripts)
    - `#img2` -- image reference

    Support types (per D-15): `direct`, `inferred`, `tentative`, `derived`

    `checked_at` (per D-16): ISO 8601 date when provenance link was last verified.

    Example in context:
    ```markdown
    - Attention mechanisms allow models to focus on relevant input tokens [prov:src-2026-03-15-vaswani-attention#sec:introduction|direct|2026-04-08]
    ```

    Source registry (per D-17): Each source summary page in `wiki/sources/` serves as the registry entry for that source. Its frontmatter contains: `id` (source_id), `path`, `title`, `source_type`, `url`, `content_hash`, `ingested_at`. This is the Dataview-native approach -- query source metadata with `TABLE source_type, ingested_at FROM "wiki/sources"`.

    Validation rules (per D-18):
    - Every `[prov:...]` reference MUST resolve to a known source ID in `wiki/sources/`
    - Every locator MUST be syntactically valid (matches one of the defined patterns)
    - If a source's `content_hash` has changed since `checked_at`, dependent claims SHOULD be marked with `epistemic_status: stale`

    **Section 7: Progressive Disclosure** (~40 lines)
    Per D-19, D-24, PROG-01, PROG-02, PROG-03:

    State the principle: all pages are structured shallow-to-deep. Top is optimized for fast LLM scanning; bottom is for human verification and deep reading.

    Rules for LLM agents:
    1. When searching for information, read `wiki/index.md` FIRST
    2. Scan TL;DR and Key Facts sections of relevant pages BEFORE reading Detail sections
    3. Only read Detail and Sources sections when shallow sections are insufficient
    4. When creating pages, TL;DR MUST be 1 short paragraph or 2-4 bullets (per D-24)
    5. Key Facts MUST be compact bullets with inline provenance markers
    6. Detail section contains full narrative, synthesis, caveats, nuance
    7. Sources section at the bottom lists human-readable source references

    Reference the per-type section orderings defined in Section 4.

    **Section 8: Wikilink and Graph Conventions** (~40 lines)
    Per D-32, D-33, D-34, OBSD-01, OBSD-03:

    Rules:
    - Use `[[Exact Page Title]]` for all cross-references in page body (per D-34)
    - Link on FIRST mention only per page; subsequent mentions are plain text (per D-32)
    - DO NOT use display aliases in wikilinks: `[[Attention Mechanism]]` not `[[Attention Mechanism|attention]]` (per D-34)
    - Use `aliases` frontmatter field for alternate names Obsidian resolves automatically
    - Red links (links to non-existent pages) are ALLOWED and intentional (per D-33) -- they signal knowledge gaps
    - DO NOT put wikilinks in YAML frontmatter -- use string IDs in frontmatter, wikilinks in body (per research Pitfall 1)
    - The `## Related Pages` section lists explicit wikilinks to connected pages
    - The `## Sources` section in page body lists human-readable source references with wikilinks to source summary pages

    The document should end with a comment: `<!-- Sections 9-16 follow below -->` to indicate continuation.
