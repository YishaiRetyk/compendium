Create `bin/lint.sh` following the established CLI helper pattern (bash wrapper + inline python3 blocks). The script:

**Header and usage:**
```bash
#!/usr/bin/env bash
# bin/lint.sh -- Wiki health-check CLI helper (AGENTS.md section 11.3).
# Detects orphan pages, missing cross-references, stale claims, contradictions,
# knowledge gaps, and structural issues. Produces wiki/maintenance/lint-report.md.
#
# Zero LLM/API calls. Deterministic, file-based checks only.
# Requires: python3 with PyYAML.
set -euo pipefail
```

**Argument parsing:** Support these flags:
- `--help` / `-h`: Print usage and exit
- `--dry-run`: Report findings without applying auto-fixes or writing report page
- `--fix`: Apply mechanical auto-fixes (stale markers, missing cross-refs where target exists). Default is report-only.
- `--category <cat>`: Run only specified category (orphan, crossref, stale, contradiction, gap, provenance, yaml). Default: all.
- First positional arg: wiki directory path (default: `wiki/`)

**Core architecture:** Use the finding accumulator pattern. Each check produces lines in format:
`severity|category|path|message`

**Implement these checks in this task:**

1. **YAML frontmatter validation** -- Use inline python3 with PyYAML. For each .md file in wiki/ (excluding index.md, log.md, maintenance/):
   - Parse YAML frontmatter between the opening and closing frontmatter delimiters
   - Check all 16 base fields present (id, title, type, status, summary, created_at, updated_at, sources, epistemic_status, tags, domains, supersedes, superseded_by, privacy, aliases, has_contradictions, knowledge_domain)
   - Validate enum fields: type in (entity, concept, source, comparison, overview), status in (active, stale, superseded, archived), epistemic_status in (sourced, mixed, tentative, stale), privacy in (local_only, cloud_safe)
   - For type: source pages, check additional fields: path, content_hash, ingested_at, source_type, compilation_status
   - Severity: error for parse failures or missing required fields

2. **Provenance validation** -- Use inline python3 with regex `\[prov:([^#\]]+)#([^|\]]+)(?:\|([^|\]]+))?(?:\|([^\]]+))?\]`:
   - Extract all `[prov:]` references from page bodies
   - Build source registry from `wiki/sources/*.md` frontmatter `id` fields
   - Flag references to source IDs not found in registry
   - Validate locator syntax matches one of: `#p<N>`, `#p<N>-<M>`, `#sec:<name>`, `#para<N>`, `#t<start>-<end>`, `#img<N>`
   - Severity: error for broken refs, warning for invalid locator syntax

3. **Orphan detection** -- Use inline python3:
   - Build resolution map: for each wiki page, collect id, title, and aliases
   - Extract all wikilinks from all page bodies using regex `\[\[([^\]|]+)(?:\|[^\]]+)?\]\]`
   - A page is orphan if NO other page's wikilinks resolve to its id, title, or any alias
   - Exclude index.md, log.md, lint-report.md from orphan candidates
   - Severity: warning

4. **Missing cross-references** -- Use inline python3:
   - For each pair of pages: if they share 2+ domains AND 2+ tags, AND they lack mutual wikilinks, flag as missing cross-reference
   - Only flag if both pages are active (status != archived, superseded)
   - Severity: warning
   - Auto-fixable: if `--fix` flag is passed, note in findings but do NOT apply auto-fix in this task (auto-fix wiring added in Plan 03)

**Finding accumulator and stdout summary:**
After all checks, sort findings by severity (error first, then warning, then info). Print compact stdout summary:

  === Wiki Lint Results ===
  Errors:   N
  Warnings: N
  Info:     N
  ~~~~~~~~~~~~~~~~~~~~~~~~
  Top findings:
    [error] path: message
    [warning] path: message
  Auto-fixes applied: N (or "none -- use --fix to apply")
  Report: wiki/maintenance/lint-report.md

Exit code: 0 if no errors, 1 if any errors found.

**Important implementation details:**
- All python3 code runs as inline heredoc blocks (python3 << 'PYEOF' ... PYEOF)
- The python3 block receives the wiki directory path as an argument
- Findings are accumulated in a bash array or temp file, then processed at the end
- Use a single comprehensive python3 block for all checks (more efficient than multiple invocations)
- The script must work with the current wiki (10 pages across 5 directories)

**Add staleness detection to bin/lint.sh's python3 block:**

Implement the staleness check as a new function in the existing python3 inline block:

1. **Hash override check** (per D-09): For each source page in `wiki/sources/`, compare `content_hash` vs `compiled_against_hash`. If they differ AND `compilation_status` is not `stale`, flag all claims linked to that source (via `[prov:source_id#...]`) as stale. Severity: warning, category: stale.

2. **Decay rate check** (per D-07, D-08, D-10):
   - For each wiki page (non-source), read `knowledge_domain` from frontmatter
   - Look up base decay period from table: software=180, science=730, biography=1825, personal-goals=90, default=365
   - For each `[prov:]` marker on the page, extract the `checked_at` date (4th field). If missing, fall back to: source page's `ingested_at`, then wiki page's `updated_at`
   - Read the claim's `[epistemic:: status]` if present, look up modifier: sourced=1.0, mixed=0.85, inferred=0.75, tentative=0.5
   - Compute effective_decay = base_days * modifier
   - If `(today - checked_at_date).days > effective_decay`, the claim is stale
   - Severity: warning, category: stale

3. **Auto-fix stale markers** (only when `--fix` flag is passed):
   - For each claim flagged as stale that does NOT already have `[epistemic:: stale]`, add the marker
   - Track which files were modified and which claims were updated
   - Add auto-fix entries to findings: `info|autofix|path|Added [epistemic:: stale] to claim at line N`

**Add lint report generation to bin/lint.sh:**

After all checks complete (including staleness), generate `wiki/maintenance/lint-report.md`:

1. Create `wiki/maintenance/` directory if it doesn't exist (`mkdir -p wiki/maintenance`)

2. Write the report page with AGENTS.md section 5 compliant frontmatter: id=lint-report, title=Lint Report, type=overview, status=active, summary="Wiki health-check findings from most recent lint run.", epistemic_status=sourced, tags=[meta, maintenance], domains=[], privacy=cloud_safe, aliases=[Lint Report], has_contradictions=false, knowledge_domain="" (plus created_at, updated_at, sources=[], supersedes, superseded_by fields). Use today's date for created_at on first run (preserve on subsequent runs) and updated_at always today.

3. Report body structure -- a markdown page with:
   - H1 heading "Lint Report"
   - Run metadata: Last run date, total findings count, auto-fixes applied count
   - H2 "Errors (N)" section with markdown table (Page | Category | Finding columns)
   - H2 "Warnings (N)" section with markdown table
   - H2 "Info (N)" section with markdown table

4. Skip report generation if `--dry-run` flag is passed.

5. After writing report, append log entry to `wiki/log.md` (only if not --dry-run). Use format:
   H2 header: `## [YYYY-MM-DD] lint | wiki health check`
   Body fields: findings (N total with per-severity breakdown), auto_fixes (N applied), report (path), pages_affected (list or "none")
