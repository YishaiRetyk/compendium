Add a contradiction detection function to the existing python3 inline block in bin/lint.sh. The function:

**Detection logic (per D-01, Research open question 1):**

1. For each wiki page (non-source, non-index, non-log), parse the body into sections (split on `## ` or `### ` headings).

2. For each section, extract all `[prov:]` markers and group by `source_id`.

3. If a section contains provenance markers from 2+ different source_ids, flag it as a **potential contradiction**. This is the mechanical heuristic -- the lint cannot do semantic analysis, but sections with claims from multiple sources are the most likely locations for disagreements.

4. For each flagged section, produce a finding:
   `warning|contradiction|<page_path>|Potential contradiction in section "<section_name>": claims from <source_a_id> and <source_b_id> (review needed)`

5. If the page already has `[contradiction:...]` markers, do NOT re-flag those specific source pairs. Only flag NEW potential contradictions not yet acknowledged.

**Important constraints:**
- This is report-only (per D-19) -- no auto-fix for contradictions
- The finding says "potential contradiction" because the lint cannot confirm semantic disagreement
- The LLM agent running the lint workflow (AGENTS.md section 11.3 step 5) reviews these findings and promotes confirmed ones to inline `[contradiction:]` markers
- Severity is always `warning` (per D-06)
- Do NOT attempt semantic analysis -- this is strictly provenance-marker-based detection

**Integration with existing code:**
- Add the contradiction check function alongside existing check functions (orphan, crossref, stale, etc.)
- Hook it into the main check orchestrator
- Ensure it's skippable via `--category` flag (category name: `contradiction`)
- Findings feed into the existing accumulator and appear in the lint report under Warnings

  <action>
Add two knowledge gap detection functions to the python3 inline block in bin/lint.sh:

**1. Red link detection (per D-20, GAP-01):**

Using the wikilink extraction and resolution map already built for orphan detection:

- Collect all unresolved wikilinks (targets that don't match any known page id, title, or alias)
- For each unresolved link, track which pages reference it and whether it appears in a TL;DR or Key Facts section
- TL;DR/Key Facts detection: check if the wikilink appears in text between a `## TL;DR` or `## Key Facts` heading and the next `## ` heading
- **Flagging rules (per D-20):**
  - Flag if the unresolved link appears on 2+ distinct pages
  - Flag if the unresolved link appears in any TL;DR or Key Facts section (regardless of frequency)
- For each flagged red link, produce:
  `info|gap|red-link:<link_target>|Unresolved wikilink on N pages: <page1>, <page2>, ... (suggest creating dedicated page)`

**2. Sparse source coverage (per D-21, D-22, GAP-02):**

- Collect all unique `knowledge_domain` values from wiki page frontmatter
- For each domain, count the number of source pages (`type: source`) that list that domain in their `domains` field
- **Maturity guardrail (per D-22):** Only run this check when:
  - Wiki has 5+ distinct domains
  - At least 3 domains have 2+ sources
  If guardrail not met, produce: `info|gap|maturity|Sparse coverage check skipped: wiki has fewer than 5 domains or fewer than 3 domains with 2+ sources`
- If guardrail met, compute median source count. Flag domains with source count < median/2 (or 0 sources):
  `info|gap|sparse:<domain>|Domain "<domain>" has N sources vs median M. Consider: <suggested question>`

**3. Question suggestions (per D-23, LINT-06):**

For each gap finding (red link or sparse coverage), append a suggested investigative question:
- Red links: "What is <link_target> and how does it relate to the pages that reference it?"
- Sparse coverage: Generate a domain-specific question. Use a simple template:
  - If domain has 0 sources: "What are your key interests or references in <domain>?"
  - If domain has few sources: "What additional perspectives on <domain> would strengthen coverage?"

**Integration:**
- Both functions hook into the main check orchestrator
- Category names: `gap` (covers both red links and sparse coverage)
- Skippable via `--category gap`
- Findings are severity: info (per D-17)
- Report-only (per D-19)
