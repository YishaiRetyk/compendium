<domain>
## Phase Boundary

Phase 13.2 is the **end-of-line milestone gate for v1.1** — it is NOT feature work. It proves all active v1.1 work (Phases 7–13.1) has been implemented, verified, documented, and checked for scope creep, then closes the milestone.

The four locked success criteria (from ROADMAP.md Phase 13.2 / REQUIREMENTS.md CLOSE-01..04):

1. **CLOSE-01** — `bin/requirements-sync.sh --strict` shows zero drift between `REQUIREMENTS.md` and phase verification artifacts across **all** v1.1 phases.
2. **CLOSE-02** — Obsidian render, non-Claude agent-parity, and genuine write-back scenarios are **re-run or explicitly audited** after Phases 12, 12.1, 12.2, 13, and 13.1 land. (These are the DEBT-01/02/04 hand-offs from Phase 13.1.)
3. **CLOSE-03** — README, docs, decision records, and roadmap consistently describe the final v1.1 feature surface, the complementary-system boundary, and explicitly deferred work.
4. **CLOSE-04** — A final scope-leak check confirms no task engine, reminder/calendar layer, high-frequency event ingest, premature scaling tier, or canonical GTD dashboard has entered v1.1.

**In scope:** CLOSE-01, CLOSE-02, CLOSE-03, CLOSE-04 (see REQUIREMENTS.md). Running the requirements-sync drift + completeness gate; auditing/re-running the three manual verifications carried over from 13.1; a docs/README/DR/roadmap consistency pass; a scope-leak audit; producing the closure verification artifacts; flipping CLOSE-01..04 to Complete; and archiving the milestone.

**Out of scope (LOCKED — these are CLOSE-04's forbidden set):** No new product features. No new schema expansion **except** fixes required by failed verification. No speculative GTD review-pattern documentation. No task engine, reminder/calendar layer, high-frequency event ingest, premature scaling tier, or canonical GTD dashboard. This phase clarifies HOW the gate runs — it does not add capabilities.

## Implementation Decisions

### DEBT-01 Obsidian render disposition (CLOSE-02)
- **D-01:** **User renders now, then the gate closes on real render evidence.** The user opens the wiki in Obsidian, runs the five fixture-scoped Dataview queries + the wikilink/graph checks per the prepared checklist, and fills the capture slot in `13.1-VERIFICATION.md`. Unlike Phase 13.1 (which deferred per D-09 prepared-and-await), Phase 13.2 takes the **"re-run"** branch of CLOSE-02, not "audit." (Rejected: audit-and-defer — chosen against because the user wants the milestone closed on actual render evidence; rejected render-now-if-quick-else-defer — user committed to rendering.)
- **D-01a (execution implication for the planner):** The phase therefore contains a **user-in-the-loop checkpoint** — execution presents the render checklist, pauses for the user to render and report the counts, then records them. Plan structure must accommodate this human checkpoint (it is the single GUI step in the gate). The render itself is expected to "just work": the 13.1 checklist already resolved the KNOWN TENSION (`.obsidianignore` is a release-manifest/graph-hygiene convention, NOT Obsidian-enforced; live `.obsidian/app.json` is `{}`, so `examples/dataview-fixtures/` IS indexed by Dataview). Expected counts: active-entities=3, sources-by-domain(alpha)=2, stale-pages=2, missing-privacy=2, pages-in-domain(alpha,active)=5.

### DEBT-02 Codex agent-parity disposition (CLOSE-02)
- **D-02:** **Accept the completed structural-diff audit; record Codex as environment-blocked — no re-run.** The Claude-vs-golden-subset structural diff (prov-locator-target EXACT match on all 6 `#sec:` targets) already stands as the agent-parity evidence. The Codex column is formally recorded as **blocked-on-host-runtime**, attributed to the live AppArmor policy. **No sudo, no sandbox remediation, no alternative-agent attempt.** (Rejected: remediate-sandbox-and-re-run — needs sudo to lift `apparmor_restrict_unprivileged_userns` and may still fail; rejected try-alt-invocation — not worth the bounded effort for a milestone-closure gate when honest structural-diff evidence already exists.)
- **D-02a (root cause, confirmed live this session):** `kernel.apparmor_restrict_unprivileged_userns = 1` on this host blocks Codex's bubblewrap sandbox from creating user namespaces (kernel `unprivileged_userns_clone = 1` allows it, but the AppArmor LSM restriction overrides). This is the exact pathology recorded in `13.1-VERIFICATION.md` ("bubblewrap … needs access to create user namespaces"). The gate documents this as a **host-environment limitation, not an agent-parity failure**, per SAFETY-GUARD honesty.

### CLOSE-03 docs-consistency + CLOSE-04 scope-leak mechanism
- **D-03:** **Manual one-time agent audit, edit-on-drift — no new `bin/` script.** Both checks are performed as a single-pass agent audit against the v1.1 feature surface (README, `docs/`, decision records, ROADMAP.md) and the forbidden-scope list (task engine, reminder/calendar layer, high-frequency event ingest, premature scaling tier, canonical GTD dashboard). Inconsistencies/drift are **fixed inline** (matches Phase 13.1's accuracy-pass edit-on-drift style). (Rejected: build a reusable `bin/check-scope-leak.sh` — over-engineering a one-time milestone gate; rejected report-only — leaves fixes as a follow-up, which defeats a closure gate. The existing primitives `bin/requirements-sync.sh --strict --require-complete`, `bin/check-neutrality.sh`, and `bin/check-privacy.sh` are reused as-is for the mechanical portions; only scope-leak + narrative-consistency are the new manual audit.)

### Closure deliverable + milestone disposition (CLOSE-01)
- **D-04:** **Full gate + auto-archive.** Phase 13.2 produces `13.2-VERIFICATION.md` **and** an independent `13.2-VERIFIER-REPORT.md` (mirroring the prior-phase format, e.g. `13-VERIFICATION.md` + `12.2-VERIFIER-REPORT.md`), flips CLOSE-01..04 to **Complete** in REQUIREMENTS.md (bullets + traceability matrix), and — as the final step of execution — runs **`/gsd-complete-milestone`** to archive v1.1. (Rejected: archive-separately and gate-only — user wants the milestone closed end-to-end in this phase.)
- **D-04a (in-scope cleanup folded into the gate):** Two items surfaced during scouting are folded into this phase so the gate can sign off cleanly:
  1. **Commit the untracked `12.2-VERIFIER-REPORT.md`** (`.planning/phases/12.2-local-wiki-write-gate/12.2-VERIFIER-REPORT.md` is currently untracked) — a closure gate that asserts committed-artifact consistency and requirements-sync zero-drift must not leave a verification artifact dangling.
  2. **Author the SC1 reframing decision record** flagged by 13.1 as a Phase 13.2 follow-up: a `wiki/decisions/dr-*.md` with `trigger_type: reframing` formalizing the renegotiation of Phase 13.1 SC1 from "graph not contaminated by `examples/`" → "`examples/` forms a VISUALLY ISOLABLE sub-graph" (the single-Excluded-files-mechanism constraint under D-03's no-`.obsidian/`-mutation rule).
