<decisions>
## Implementation Decisions

### Curation workflow (calibration-then-extrapolation pattern)
- **D-01:** Curation proceeds in three steps:
  1. **Calibration sample:** A 20-line sample is drawn from `.planning/backlog-neutrality-denylist-candidate.txt` proportionally across the 3 source clusters (≈10 from `personal-decision-patterns.md`, ≈9 from `personal-decision-journal.md`, ≈1 from `agents-md-size-risk.md`) using deterministic seed `42` so the sample is reproducible.
  2. **Interactive line-by-line:** A small bash/python script presents each of the 20 sample lines and prompts the user for a binary `keep` / `skip` decision. The script records each decision plus the term to a calibration log file (e.g., `.planning/phases/12.1-neut-08-personal-term-denylist-curation/calibration-decisions.txt`).
  3. **Claude-extrapolated draft + user review:** Claude reads the candidate file plus the calibration log, infers the operative rubric the user is applying (the formal SPEC.md rubric is the prior; calibration decisions resolve borderline cases), and produces a draft kept-list for all 855 lines with a brief rationale per kept term. The user reviews/edits the draft before merging into `.neutrality-denylist.txt`. This is the only step that mutates the live denylist.
- **D-02:** Calibration sample uses Python `random.seed(42); random.sample(...)` with proportional stratification across clusters. The seed is documented inline in the calibration script so re-running reproduces the same 20 lines. Rationale: avoids over-sampling the 19-line generic cluster and lets future curators (or the agent-mediated loop, if promoted) reproduce the calibration deterministically.
- **D-03:** Interactive prompt format is intentionally minimal: just `keep` / `skip` per line. Claude infers reasoning from the term's surface features plus the binary decision; no per-line free-text rationale is collected during calibration. Rationale: low operator friction; keeps the rubric inference focused on the term's intrinsic features (proper noun? hyphenated? generic English?).
- **D-04:** Claude's draft output format is grouped by decision (kept-list + rejected-list with reject-class label per term), so the user can grep/skim rejected terms by class to spot-check the inference. Inline per-kept-term rationale is short (one phrase per term, e.g., `"hyphenated personal-vault identifier"` or `"proper noun"`).

### Fixture test scope
- **D-05:** A new directory `tests/phase-12.1/` is created with a `run.sh` aggregator + `test_neut08_live_denylist_contract.sh`. Mirrors the `tests/phase-07/` through `tests/phase-11/` per-phase directory pattern. Standalone, picked up by any aggregator that walks `tests/*/run.sh`.
- **D-06:** Contract test is the **Any-NEUT-08-term contract** (lightest of three options considered):
  - Test parses `.neutrality-denylist.txt`, locates the first term under any `# Category:` header containing `NEUT-08` (case-insensitive substring match), and uses it as the assertion anchor.
  - Test seeds the anchor term in a temp public-path fixture file (e.g., a markdown file under a fixture root) and runs `bin/check-neutrality.sh --root <fixture-root> --denylist .neutrality-denylist.txt`; asserts exit code 2 and the anchor term in the hits.
  - Negative-control: same fixture with the anchor term removed (or replaced with a benign string); asserts exit 0.
  - **Rationale (per user):** "We're not likely to one-shot a CI; another person might prefer it different." The lightest contract test is correct under the expectation of iteration. Avoids brittleness to re-curation: test passes as long as ANY NEUT-08 term exists in the live denylist and is enforceable.
  - **Edge case:** test fails fast (with a clear error message) if zero NEUT-08-tagged terms exist in the live denylist — guards against vacuous-pass-on-empty.

### Category header structure
- **D-07:** All curated additions land under a single new unified category header in `.neutrality-denylist.txt`: `# Category: Personal-vault terms expanded curation (NEUT-08, 2026-05-02)`. One header, many terms — matches the existing pattern (Kahneman: 1 header / 8 entries; Personal-decision archived: 1 header / 8 entries).
- **D-08:** Source-cluster traceability is NOT preserved inside the denylist file (no per-cluster sub-headers, no inline `# from:` comments — the latter is broken under the existing `load_denylist` parser at `bin/check-neutrality.sh:147-157` since it does not strip inline trailing comments). Per-cluster rejection counts are captured in `12.1-VERIFICATION.md` and `12.1-DISCUSSION-LOG.md` instead, preserving the audit trail without polluting the live denylist file.

### Verification artifact shape
- **D-09:** `12.1-VERIFICATION.md` follows the Phase 7 mirror format: phase-summary frontmatter (`reverify_date`, `score`, `human_verification_resolved` / `_deferred` if applicable); goal-achievement table mapping the 5 ROADMAP.md success criteria to evidence with file-path citations; required-artifact list; explicit `bin/requirements-sync.sh --strict --phase 12.1` and `--require-complete --phase 12.1` exit-code evidence. Auto-mode default after Phase 7 / Phase 12 precedent.
- **D-10:** Verification artifact additionally records: kept-term count (N), rejected-class breakdown (e.g., generic English ≈X, ambiguous middle ≈Y, off-rubric ≈Z), fixture-test exit codes (positive + negative-control), pre-curation `bash bin/check-neutrality.sh; echo $?` output (showing exit 2 with the lint-report.md hits) and post-curation `bash bin/check-neutrality.sh; echo $?` output (showing exit 0), and the REQUIREMENTS.md before/after diff for NEUT-08.

### Code constraints derived from gate parser (D-08 root cause)
- `bin/check-neutrality.sh` `load_denylist()` (lines 147–157) reads each line, strips whitespace, skips empty lines and lines starting with `#`. **It does NOT strip trailing inline `# ...` comments.** Any line of the form `term # comment` would be loaded as the literal string `term # comment` (lowercased) and matched as substring against file contents — never matching anything. Implication: per-term inline source attribution is technically infeasible without modifying the loader (forbidden by SPEC). Block-comment-style inter-term `# from:` lines would work but were rejected per D-07 in favor of the simpler unified header.

<specifics>
## Specific Ideas

- **User favors calibration-then-extrapolation over simpler curation extremes.** Rejected pure editor-only (too tedious for 855 lines), pure Claude-only (LLM intermediates a security-adjacent decision), and pure interactive (slowest). The hybrid keeps the rigorous human-in-loop calibration on a small representative sample, then leverages Claude's pattern-matching for the bulk while preserving final human review. Signals: rigor with low manual labor; trust-but-verify Claude.
- **User explicitly chose the lightest contract-test scope (Any-NEUT-08).** Rationale stated: "We're not likely to one-shot a CI; another person might prefer it different." Signals: don't over-invest in proving correctness when iteration is expected. The All-new-terms recommendation was withdrawn after this insight.
- **User flagged a meta-pattern worth capturing as future capability.** "CI runs → agent reviews result → prompts human about failures → human specifies intent → agent acts on it and improves CI for next time." Recognized as a real adaptive-policy pattern that maps cleanly onto compendium primitives (DRs as rationale memory; Phase 12 boundary preserved by splitting execution-side vs memory-side). Captured as deferred backlog item.
- **User chose unified single category over per-cluster grouping.** Reasoning: matches existing 1-header-many-terms pattern; source-cluster traceability is bookkeeping not categorical truth; simpler-to-iterate when actual organizing pressure shows up. Signals: prefer consistency with established convention; resist premature structure.
