# Plan 03 Summary — Calibration + Curation + Append

## What was built

A curated 7-term expansion to `.neutrality-denylist.txt` under a single
new unified header `# Category: Personal-vault terms expanded curation
(NEUT-08, 2026-05-02)`. The curation flow followed the calibration-
then-extrapolation pattern locked in CONTEXT.md D-01..D-04, with one
mid-stream rubric revision (escalation per Task 4 resume signal).

## Curation flow

1. **Task 1** — authored `calibration-script.py` per the RESEARCH.md
   skeleton (seed=42, proportional stratification across 3 source
   clusters: agents-md-size-risk=1, personal-decision-patterns=10,
   personal-decision-journal=9 → total 20).

2. **Task 2** — interactive calibration. User reviewed the deterministic
   20-line stratified sample and skipped every entry. The sample
   contained no hyphenated vault-unique identifiers; the only borderline
   candidate was `sunk-cost` (well-known economics term, not vault-coined).
   Result: `calibration-decisions.txt` with 0 keep / 20 skip.

3. **Task 3** — initial extrapolation under the original SPEC rubric
   (hyphenated identifier unique to vault) yielded N=1 (`pre-committing`,
   gerund extension of denied root). Phase 7's starter category was
   already comprehensive for hyphenated vault-coined terms.

4. **Task 4** — user escalated the N=1 result. Investigation surfaced
   two real coverage gaps:

   - **Gap A**: Spaced multi-word phrases coined in archived journal
     sources that the hyphenated-only rubric missed. Precedent: existing
     denylist already uses spaced forms (`loss aversion`, `system 1`,
     `cognitive biases`).
   - **Gap B**: Popular cog-bias terms used heavily in the journal
     source whose appearance in public template paths would betray
     vault provenance via LLM-mediated example-leak. The dominant leak
     vector in this repo's authoring pattern: Claude pattern-matches on
     what's heavily present in the user's repo when generating examples
     in public-facing files.

   Revised rubric: SPEC §Constraints baseline + defense-in-depth
   extension covering (a) and (b).

5. **Task 5** — appended 7 kept terms under the unified header. All 7
   pre-screened as 0-hit on the live public tree (FP-safe).
