## Curation workflow

### Q1 — Curation approach

| Option | Description | Selected |
|--------|-------------|----------|
| Editor-only pass | Open candidate file in editor, hand-pick lines visually using SPEC rubric. Zero engineering. ~30–60min for 855 lines. | |
| Claude-assisted draft, you review | Claude reads candidate file applying SPEC rubric, proposes draft promoted-list, user reviews/edits. Fast. LLM intermediates a security-adjacent decision. | |
| Prefilter script then review | One-shot script drops obvious generic English, leaves shortlist for editor review. Mechanical first pass; risk of dropping legitimate hyphenated identifiers. | |
| Interactive line-by-line | Bash/python script prompts keep/skip per term. Most rigorous, slowest. | |
| **Hybrid: 20-line interactive calibration → Claude extrapolated draft → user review** (free-text — user-proposed) | User does interactive line-by-line on 20 random lines as calibration sample; Claude infers operative rubric from binary decisions; Claude proposes draft for all 855; user reviews/edits before merge. | ✓ |

**User's choice:** Hybrid calibration-then-extrapolation pattern (free-text response combining elements of options 2 and 4).
**Notes:** User signaled a preference for rigor with low manual labor. Calibration sample preserves human-in-loop decision quality on a small representative sample; Claude's extrapolation leverages pattern-matching for the bulk; final user review preserves trust-but-verify on Claude's output.

### Q2 — Calibration sample drawing

| Option | Description | Selected |
|--------|-------------|----------|
| Proportional + deterministic seed | 20 lines drawn proportionally across 3 source clusters (≈10 / ≈9 / ≈1), fixed seed (42) for reproducibility. | ✓ |
| Uniform random + deterministic seed | 20 lines uniform-random across 855, fixed seed. Simpler. Likely 0–1 hits from small generic cluster. | |
| Stratified diverse mix | Claude picks 20 spanning recognizable patterns (~5 obvious-keep, ~10 ambiguous, ~5 obvious-reject). Better signal-per-line; less random. | |
| All 19 from generic cluster + 1 each from others | Burn small generic cluster fully + 1 representative per larger cluster. | |

**User's choice:** Proportional + deterministic seed.
**Notes:** Reproducibility of the sample is load-bearing — future curators (or the deferred agent-mediated loop) can re-run the same calibration. Proportional stratification avoids over-sampling the small generic cluster.

## Category header structure

### Q5 — Header layout in `.neutrality-denylist.txt`

| Option | Description | Selected |
|--------|-------------|----------|
| One category per source cluster | Up to 3 new headers, one per candidate-file cluster. Header sprawl risk; small clusters yield 0–1 entry headers. | |
| **Single unified category** | One new `# Category: Personal-vault terms expanded curation (NEUT-08, 2026-05-02)` header. Matches existing 1-header-many-terms pattern. | ✓ |
| Sub-grouped by rubric class | 2 headers: proper-nouns/codenames + hyphenated-identifiers. Rubric-aligned. Costs: classification overhead during curation; fuzzy boundaries. | |
| Single category + per-term inline `# from:` | Unified header + trailing inline source comment per term. **REJECTED on correctness:** existing `bin/check-neutrality.sh` loader (lines 147–157) does NOT strip trailing inline comments — would silently neuter the entries. Reframed option (block-level `# from:` comments between groups) was viable but rejected in favor of simplicity. | |

**User's choice:** Single unified category.
**Notes:** Three reasons given: (1) existing `.neutrality-denylist.txt` already follows 1-header-many-terms (Kahneman 8 / Personal-decision-archived 8); (2) source-cluster traceability is bookkeeping not categorical truth — both personal-decision sources are equivalently "personal-vault content from before v1.0"; (3) simplest structure today is easiest to refactor later when actual organizing pressure shows up. Per-cluster rejection counts captured in `12.1-VERIFICATION.md` instead.
