## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Curation workflow (calibration-then-extrapolation pattern)
- **D-01:** Curation proceeds in three steps:
  1. **Calibration sample:** A 20-line sample is drawn from `.planning/backlog-neutrality-denylist-candidate.txt` proportionally across the 3 source clusters (≈10 from `personal-decision-patterns.md`, ≈9 from `personal-decision-journal.md`, ≈1 from `agents-md-size-risk.md`) using deterministic seed `42` so the sample is reproducible.
  2. **Interactive line-by-line:** A small bash/python script presents each of the 20 sample lines and prompts the user for a binary `keep` / `skip` decision. The script records each decision plus the term to a calibration log file (e.g., `.planning/phases/12.1-neut-08-personal-term-denylist-curation/calibration-decisions.txt`).
  3. **Claude-extrapolated draft + user review:** Claude reads the candidate file plus the calibration log, infers the operative rubric the user is applying (the formal SPEC.md rubric is the prior; calibration decisions resolve borderline cases), and produces a draft kept-list for all 855 lines with a brief rationale per kept term. The user reviews/edits the draft before merging into `.neutrality-denylist.txt`. This is the only step that mutates the live denylist.
- **D-02:** Calibration sample uses Python `random.seed(42); random.sample(...)` with proportional stratification across clusters. The seed is documented inline in the calibration script so re-running reproduces the same 20 lines.
- **D-03:** Interactive prompt format is intentionally minimal: just `keep` / `skip` per line. Claude infers reasoning from the term's surface features plus the binary decision; no per-line free-text rationale is collected during calibration.
- **D-04:** Claude's draft output format is grouped by decision (kept-list + rejected-list with reject-class label per term), so the user can grep/skim rejected terms by class to spot-check the inference. Inline per-kept-term rationale is short (one phrase per term).

#### Fixture test scope
- **D-05:** A new directory `tests/phase-12.1/` is created with a `run.sh` aggregator + `test_neut08_live_denylist_contract.sh`. Mirrors the `tests/phase-07/` through `tests/phase-11/` per-phase directory pattern.
- **D-06:** Contract test is the **Any-NEUT-08-term contract** (lightest of three options considered):
  - Test parses `.neutrality-denylist.txt`, locates the first term under any `# Category:` header containing `NEUT-08` (case-insensitive substring match), and uses it as the assertion anchor.
  - Test seeds the anchor term in a temp public-path fixture file (e.g., a markdown file under a fixture root) and runs `bin/check-neutrality.sh --root <fixture-root> --denylist .neutrality-denylist.txt`; asserts exit code 2 and the anchor term in the hits.
  - Negative-control: same fixture with the anchor term removed (or replaced with a benign string); asserts exit 0.
  - **Edge case:** test fails fast (with a clear error message) if zero NEUT-08-tagged terms exist in the live denylist — guards against vacuous-pass-on-empty.

### Pattern 3: Self-locating contract test (Any-NEUT-08-term)
**What:** Test parses `.neutrality-denylist.txt` at runtime, finds the first term under any `# Category:` header containing `NEUT-08`, and uses it as the assertion anchor.
**When to use:** When the test must remain valid across re-curations of the underlying data.
**Example pseudocode:**
```bash
# Locate anchor term (first non-comment, non-empty line after a # Category: ... NEUT-08 ... header)
ANCHOR=$(awk '
  /^# *Category:.*NEUT-08/i { in_block=1; next }
  /^# *Category:/           { in_block=0; next }
  in_block && /^[[:space:]]*$/ { next }
  in_block && /^#/             { next }
  in_block && NF               { print; exit }
' .neutrality-denylist.txt)
[ -n "$ANCHOR" ] || { echo "FAIL: no NEUT-08-tagged term in live denylist"; exit 1; }
```

### Anti-Patterns to Avoid
- **Inline `# from:` comments per term:** the `load_denylist()` parser (`bin/check-neutrality.sh:147-157`) does NOT strip trailing comments. `term # comment` would be loaded as the literal string `term # comment` (lowercased) and never match anything in scanned files. Silent neutering. **Rejected by D-08.**
- **Pinning a specific term in the contract test:** brittle to re-curation. **Rejected by D-06.**
- **Modifying `bin/check-neutrality.sh`:** non-goal locked in SPEC.md and CONTEXT.md.
- **Filtering / rewriting the body of `wiki/maintenance/lint-report.md`:** non-goal; the file legitimately needs to name denylisted terms. **Rejected by SPEC.md.**
- **One category per source cluster:** sprawl risk; `agents-md-size-risk.md` cluster expected to yield ~0 promotions, leaving an empty-or-1-term header. **Rejected by D-07.**

## Common Pitfalls

### Pitfall 1: Empty NEUT-08 category traps the contract test
**What goes wrong:** If Wave 0 lands the test scaffold and Wave 1b has not yet appended any terms under the new `# Category: ... NEUT-08 ...` header, the contract test finds zero anchors and (per D-06's edge-case clause) MUST fail fast with a clear error message — not pass vacuously.
**Why it happens:** Test scaffold landing before curation = Wave 0 RED is the intended state.
**How to avoid:** Document the Wave 0 RED expectation in the plan; only assert `tests/phase-12.1/run.sh` GREEN at Wave 2 milestone (after Wave 1b merge into `.neutrality-denylist.txt`).
**Warning signs:** A plan that asserts `tests/phase-12.1/run.sh` exit 0 in Wave 0 will be incorrectly RED-flagged as a regression.

### Pitfall 2: Live-tree gate exit-0 evidence captured before curation
**What goes wrong:** The frontmatter fix on `wiki/maintenance/lint-report.md` (Wave 1a) restores `bin/check-neutrality.sh` to exit 0 *independently* of any curation work (Wave 1b). If a verifier captures `bash bin/check-neutrality.sh; echo $?` after Wave 1a but before Wave 1b, the evidence is misleadingly clean — exit 0 happens BEFORE any new NEUT-08 terms are merged, so requirement #2 is technically satisfied without exercising requirement #1.
**Why it happens:** The lint-report.md regression and the curation work are independent; both exit-2-causes coincidentally.
**How to avoid:** D-10 requires capturing `bash bin/check-neutrality.sh; echo $?` BOTH pre-curation (showing the lint-report.md hits) AND post-curation (showing exit 0 with new terms in the denylist). Verification artifact must show both. Pre-state evidence MUST be captured first or pulled from this RESEARCH.md (see Pitfall-2 evidence below).
**Warning signs:** VERIFICATION.md only shows post-state exit 0 with no pre-state diff or with pre-state captured AFTER frontmatter fix.
**Pre-state evidence captured 2026-05-02 (this research session):**
```
$ bash bin/check-neutrality.sh; echo "exit: $?"
wiki/maintenance/lint-report.md:38: kahneman
wiki/maintenance/lint-report.md:39: personal-decision-journal
```

### Pitfall 3: Calibration yields zero "keep" decisions
**What goes wrong:** The 20-line stratified sample is dominated by generic English (≈10 from `personal-decision-patterns.md` + ≈9 from `personal-decision-journal.md` + ≈1 from the tiny mostly-generic `agents-md-size-risk.md` cluster). The candidate file is the deterministic `--suggest-denylist` output; spot-checks show terms like `accept`, `action`, `addition`, `after`, `ability` etc. — almost all generic dictionary words by the SPEC.md rubric. A plausible calibration outcome is 0–2 keeps out of 20.
**Why it happens:** SPEC rubric explicitly rejects generic single-word English vocabulary; the candidate file is mostly generic vocabulary.
**How to avoid:** The plan must NOT assume Wave 1b produces ≥10 terms. Acceptance criterion #1 says `N > 0` — even a single-term promotion satisfies the curated-merge requirement (provided the curation rubric is honored). If calibration yields 0 keeps, the planner instructs the executor to (a) inspect whether seed=42 happened to draw an unrepresentative sample, (b) if yes, perform a one-time additional non-calibration pass (Claude scans the 855 lines for hyphenated identifiers / multi-word phrases / proper nouns, since those are categorically the targets), (c) if no terms qualify under any pass, escalate to user.
**Warning signs:** Plan assumes specific N; plan estimates "minutes per term" without bounding-N analysis.

### Pitfall 4: Anchor in contract test exits the awk loop too early
**What goes wrong:** If the awk anchor-extraction (Pattern 3 above) is given a category header that legitimately has zero terms beneath it (e.g., the unified header was added but the merge step appended terms to the wrong location), the loop exits without finding an anchor. This silently masks a different failure (terms not under the right header) as the "zero-NEUT-08-terms" failure.
**Why it happens:** awk's `in_block && NF { print; exit }` exits at first match; absence-of-match is silent.
**How to avoid:** Test ASSERTS the anchor extraction succeeded with a specific error string ("no NEUT-08-tagged term found in `.neutrality-denylist.txt` — vacuous-pass guard"). Distinct from negative-control failure messages.
**Warning signs:** Test passes but produces no output describing which anchor it picked; debugging takes minutes.

### Pitfall 5: Verification artifact's kept-term count drifts from actual diff
**What goes wrong:** SPEC requirement #5 acceptance ties kept-term count in `12.1-VERIFICATION.md` to `git diff <phase-base>..HEAD -- .neutrality-denylist.txt | grep -cE '^\+[^#+]'`. If the executor edits the verification artifact then later edits the denylist (e.g., user removes 1 term during review), the count desyncs.
**Why it happens:** Author-VERIFICATION-then-edit-denylist ordering.
**How to avoid:** Author 12.1-VERIFICATION.md AFTER the denylist is locked. Compute the count via the documented git-diff command and paste the actual number plus the command for reproducibility.
**Warning signs:** Verification artifact has count "≈N" or "approximately N"; SPEC requires exact match.

### Calibration script skeleton (Python; CONTEXT D-01..D-03 + Discretion)
```python
#!/usr/bin/env python3
"""
Phase 12.1 calibration script — draws 20 lines proportionally stratified
across the 3 source clusters in .planning/backlog-neutrality-denylist-candidate.txt
with deterministic seed=42; prompts user keep/skip per line; writes decisions
to calibration-decisions.txt.

Per CONTEXT.md D-02: seed=42 is load-bearing for reproducibility.
Per CONTEXT.md D-03: prompt is binary keep/skip only; no free-text rationale.
"""
import random
import re
import sys
from pathlib import Path

CANDIDATE = Path(".planning/backlog-neutrality-denylist-candidate.txt")
DECISIONS = Path(
    ".planning/phases/12.1-neut-08-personal-term-denylist-curation/"
    "calibration-decisions.txt"
)
SAMPLE_TOTAL = 20
SEED = 42

def parse_clusters(path: Path) -> dict[str, list[str]]:
    clusters: dict[str, list[str]] = {}
    current = None
    for line in path.read_text(encoding="utf-8").splitlines():
        if line.startswith("# source:"):
            current = line[len("# source:"):].strip()
            clusters[current] = []
        elif current and line.strip() and not line.startswith("#"):
            clusters[current].append(line.strip())
    return clusters

def stratified_sample(clusters: dict[str, list[str]], total: int) -> list[tuple[str, str]]:
    """Proportional stratification: cluster_quota = round(total * cluster_size / grand_total)."""
    grand = sum(len(v) for v in clusters.values())
    out: list[tuple[str, str]] = []
    rng = random.Random(SEED)
    for source, terms in clusters.items():
        quota = max(1, round(total * len(terms) / grand)) if terms else 0
        # Cap at population size; over-shoot fixed by trimming to total below
        quota = min(quota, len(terms))
        picks = rng.sample(terms, quota)
        out.extend((source, term) for term in picks)
    # Deterministic trim if rounding overshoots
    return out[:total]

def main() -> int:
    if not CANDIDATE.exists():
        print(f"ERROR: candidate file missing: {CANDIDATE}", file=sys.stderr)
        return 1
    clusters = parse_clusters(CANDIDATE)
    sample = stratified_sample(clusters, SAMPLE_TOTAL)
    DECISIONS.parent.mkdir(parents=True, exist_ok=True)
    with DECISIONS.open("w", encoding="utf-8") as fh:
        fh.write(f"# Phase 12.1 calibration decisions (seed={SEED}, n={len(sample)})\n")
        fh.write(f"# Format: <decision>\\t<term>\\t<source-cluster>\n")
        for source, term in sample:
            while True:
                resp = input(f"[{source.split('/')[-1]}] {term!r}  keep/skip: ").strip().lower()
                if resp in ("keep", "k", "y"):
                    fh.write(f"keep\t{term}\t{source}\n"); break
                if resp in ("skip", "s", "n"):
                    fh.write(f"skip\t{term}\t{source}\n"); break
    print(f"Wrote {len(sample)} decisions to {DECISIONS}")
    return 0

if __name__ == "__main__":
    sys.exit(main())
```

### Contract test skeleton (bash; CONTEXT D-05, D-06)

```bash
#!/usr/bin/env bash
# tests/phase-12.1/test_neut08_live_denylist_contract.sh
# Any-NEUT-08-term contract: parse live denylist for first NEUT-08-tagged term,
# seed it in a public-path fixture, assert gate fires (exit 2 + hit);
# negative-control: remove the term, assert gate clean (exit 0).
set -euo pipefail
SCRIPT_DIR=$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)
REPO_ROOT=$(cd "$SCRIPT_DIR/../.." && pwd)
cd "$REPO_ROOT"

DENYLIST=".neutrality-denylist.txt"
SCRIPT="bin/check-neutrality.sh"

# 1. Locate anchor: first non-comment, non-empty line under any # Category: ... NEUT-08 ... header
ANCHOR=$(awk '
  /^# *[Cc]ategory:.*NEUT-08/ { in_block=1; next }
  /^# *[Cc]ategory:/          { in_block=0; next }
  in_block && /^[[:space:]]*$/ { next }
  in_block && /^#/             { next }
  in_block && NF               { print; exit }
' "$DENYLIST")

if [ -z "$ANCHOR" ]; then
  echo "FAIL: no NEUT-08-tagged term found in $DENYLIST (vacuous-pass guard)" >&2
  exit 1
fi
echo "anchor term: $ANCHOR"

# 2. Build hermetic fixture root with the anchor seeded in a public-path file
FIX=$(mktemp -d)
trap 'rm -rf "$FIX"' EXIT
mkdir -p "$FIX/wiki" "$FIX/docs"
echo "# Test fixture\nThis page contains the term $ANCHOR for leak testing." > "$FIX/wiki/leak.md"

# 3. Positive: gate must fire (exit 2 + hit on anchor)
set +e
OUT=$(bash "$SCRIPT" --root "$FIX" --denylist "$REPO_ROOT/$DENYLIST" 2>&1)
RC=$?
set -e
if [ "$RC" -ne 2 ] || ! echo "$OUT" | grep -qF "$ANCHOR"; then
  echo "FAIL positive: expected exit 2 with hit on '$ANCHOR'; got exit $RC" >&2
  echo "$OUT" >&2
  exit 1
fi
echo "PASS positive: gate fires on '$ANCHOR'"

# 4. Negative-control: replace anchor with benign string; gate must be clean
sed -i.bak "s/$ANCHOR/REDACTED/g" "$FIX/wiki/leak.md" && rm "$FIX/wiki/leak.md.bak"
set +e
OUT2=$(bash "$SCRIPT" --root "$FIX" --denylist "$REPO_ROOT/$DENYLIST" 2>&1)
RC2=$?
set -e
if [ "$RC2" -ne 0 ]; then
  echo "FAIL negative-control: expected exit 0 after removal; got exit $RC2" >&2
  echo "$OUT2" >&2
  exit 1
fi
echo "PASS negative-control: gate clean after removal"
echo "test_neut08_live_denylist_contract: 2 pass / 0 fail"
```
