## Inline residue pattern

### Q5. What stays inline in §4 after extraction?

| Option | Description | Selected |
|--------|-------------|----------|
| Bare pointer | Header + purpose/when-to-use/section-order/frontmatter + one-line pointer. Maximum token savings. | |
| 2–3 bullet capsule + pointer | Same as bare + micro-summary ("Example subject: X. Demonstrates A, B, C.") before pointer. | ✓ |
| One representative inline + 5 pointers | Keep entity example fully inline, externalize the other 5. | |

**User's choice:** 2–3 bullet capsule + pointer.
**Notes (verbatim user rationale):** "You already decided to do the deeper extraction with no hard ceiling, that means you can afford a small amount of inline context. A micro-summary preserves readability and reduces the risk that the core spec becomes too skeletal. It still gives you almost all the savings, without keeping a full example inline. A good residue shape per type is: purpose / when to use, section order, required frontmatter, 2–3 bullets saying what the worked example demonstrates, See: schema/examples/<type>.md."
