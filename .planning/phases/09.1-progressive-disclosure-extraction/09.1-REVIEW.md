### IN-01: Two `grep -c` command substitutions still unguarded (pass-only-by-luck)

**Files:**
- `tests/phase-09.1/test_agents_section_4_residue.sh:18`
- `tests/phase-09.1/test_docs_reference_new.sh:13`

**Issue:** Two `grep -c` invocations in command substitution under `set -euo pipefail` are NOT guarded with `|| true`:

```bash
# test_agents_section_4_residue.sh:18
count="$(grep -cE '^See: schema/examples/(entity|concept|source-summary|comparison|overview|decision)\.md for a concrete filled-in instance\.$' "$A")"

# test_docs_reference_new.sh:13
dataview_count="$(grep -cE '^```dataview$' "$DQ")"
```

These currently pass because the post-extraction state has 6 and 5 matches respectively (grep returns exit 0 on a match). However, the IDENTICAL pattern was already auto-fixed in `test_dataview_fences.sh` (Phase 09.1 SUMMARY auto-fix #3) precisely because zero matches makes `grep -c` exit 1 and `set -e` aborts the script before the assertion can produce a clear FAIL message.

If a future regression broke the §4 residue extraction (zero `See:` pointers) or the cookbook fences (zero ```dataview``` blocks), the script would abort silently with no diagnostic instead of emitting the intended "FAIL: expected N, found 0" message. The test still fails (correct outcome), but the error is harder to triage.

**Fix:** Apply the same `|| true` guard used in `test_dataview_fences.sh`:

```bash
count="$(grep -cE '...' "$A" || true)"
dataview_count="$(grep -cE '^```dataview$' "$DQ" || true)"
```

This is a defensive consistency cleanup — same family of bug as the three already auto-fixed during Phase 09.1 execution. Not blocking because all current matches are non-zero, but worth landing in the next maintenance pass for parity with the rest of the suite.

### IN-02: Display alias `[[Transformer Architecture|Transformers]]` preserved verbatim in `schema/examples/overview.md`

**File:** `schema/examples/overview.md:29`

**Issue:** The example body contains `[[Transformer Architecture|Transformers]]`, which violates AGENTS.md §8 rule 3 ("DO NOT use display aliases") and §3 ("DO NOT use display aliases in wikilinks"). This text was preserved verbatim from the pre-extraction §4.5 worked example block.

This is tolerated by design: the file carries `example: true`, and AGENTS.md §5 specifies that lint MUST skip pages with `example: true`. The original AGENTS.md source had the same violation in the same line — the extraction faithfully preserves the historical content rather than silently editing it.

However, since these `schema/examples/<type>.md` files are explicitly intended as canonical reference instances that LLM agents may consult to learn the page-type shape, an LLM reading `overview.md` could reasonably infer that display aliases ARE permitted (since the canonical example uses one). This creates a subtle teaching-by-example contradiction with the §8 normative rule.

**Fix options (any one would resolve, in order of least disruption):**

1. **Add an inline HTML comment** noting the historical-preservation context:
   ```markdown
   <!-- Note: the [[Title|Alias]] display-alias form below is preserved verbatim
        from the pre-extraction AGENTS.md §4.5 worked example. AGENTS.md §8
        rule 3 prohibits display aliases in canonical pages — examples with
        `example: true` are exempt from lint per §5. New pages should use the
        bare `[[Transformer Architecture]]` form. -->
   ```

2. **Edit the example to use the bare-link form** `[[Transformer Architecture]]`. The display alias adds nothing semantic; it was a stylistic choice in the original draft. A clean example better serves the teach-by-example purpose. This is technically a content edit rather than a verbatim preservation, but the change is one-token and aligns the example with the spec it illustrates.

3. **Leave as-is** if D-07 verbatim-preservation outweighs the teaching-correctness concern. (The current state is consistent with the explicit phase decision; calling it out here ensures the choice is visible for later maintainers.)

Not blocking. The `example: true` lint exemption mechanism is working as designed; this is a documentation-quality observation, not a correctness bug.

### IN-03: `docs/reference/dataview-queries.md` and `commit-examples.md` "See also" link to README that may not exist yet

**Files:**
- `docs/reference/dataview-queries.md:58`
- `docs/reference/commit-examples.md:26`

**Issue:** Both new reference files end with:

```markdown
## See also

- [AGENTS.md](../../AGENTS.md)
- [../README.md](../README.md)
```

The `../README.md` link resolves to `docs/README.md`. If `docs/README.md` does not exist (or has a different role), this is a broken relative link emitted by both new files. The pattern was likely cargo-culted from the sibling `docs/reference/ci.md` shape.

This was not flagged by the test suite because `test_docs_reference_new.sh` only checks for the H1 presence (`grep -q '^# '`), not for "See also" link validity.

**Fix:** Either:

1. Verify `docs/README.md` exists and serves as a meaningful index target, OR
2. Drop the `../README.md` line from both files if the link is broken, OR
3. Replace with a direct link to `docs/reference/index.md` if that is the intended index

Note: This is purely a doc-hygiene concern. The tests do not gate on this and the extraction is structurally correct. Worth checking during Phase 12 (DEBT scope) or any future `docs/` reorganization.
