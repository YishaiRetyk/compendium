### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed bash parser error in `tests/phase-09.1/test_docs_reference_new.sh`**
- **Found during:** Task 1 verification gate (after creating the 9 new files).
- **Issue:** Line 14 contained `'```dataview'` literal inside a double-quoted error message string. Bash's parser sees three backticks inside `"..."` as command substitution start, fails with `unexpected EOF while looking for matching `\`'`, and refuses to even parse the file (`bash -n` fails).
- **Fix:** Replaced `'```dataview'` with the plain text `dataview` in the error message — semantically identical, no parse failure.
- **Files modified:** `tests/phase-09.1/test_docs_reference_new.sh` (line 14)
- **Commit:** `bdcc2fe` (bundled into atomic extraction commit)

**2. [Rule 1 - Bug] Fixed bash parser error in `tests/phase-09.1/test_dataview_fences.sh`**
- **Found during:** Task 1 verification gate.
- **Issue:** Same backtick-in-double-quoted-string parse bug on lines 17 and 23 (`'```dataview'` and `'```markdown'` literals inside error messages). Identical pattern to the previous bug, separately introduced because Plan 09.1-01 created both files independently.
- **Fix:** Replaced both occurrences with plain text in the error messages.
- **Files modified:** `tests/phase-09.1/test_dataview_fences.sh` (lines 17, 23)
- **Commit:** `bdcc2fe`

**3. [Rule 1 - Bug] Fixed `set -e` + `grep -c` in command substitution in `tests/phase-09.1/test_dataview_fences.sh`**
- **Found during:** Task 1 verification gate (test still failed silently after the parser fix — exited 1 with no output).
- **Issue:** The script captures `markdown_opens="$(grep -cE '^```markdown$' "$DQ")"`. Under `set -euo pipefail`, when `grep -c` finds zero matches it exits 1, and `set -e` propagates the failure through command substitution, aborting the script before the `[ "$markdown_opens" -eq 0 ]` test can run. The intended assertion (zero matches = PASS) was unreachable. The same bug applies to the `dataview_opens` capture, but it would not have triggered in practice because the post-extraction count is 5 (non-zero, grep returns 0).
- **Fix:** Appended `|| true` to both `grep -c` command substitutions so the exit code is suppressed for the assignment.
- **Files modified:** `tests/phase-09.1/test_dataview_fences.sh` (lines 15, 21)
- **Commit:** `bdcc2fe`

**4. [Rule 1 - Bug] Fixed §16-scoped absence check in `tests/phase-09.1/test_agents_section_16.sh`**
- **Found during:** Task 2 final aggregator run (10/11 with one failure).
- **Issue:** The test asserted `! grep -q 'reflect(q1-review): restructure AI safety domain' AGENTS.md` to confirm the former §16 Appendix B content was removed. But the same example string also appears in the §3 commit-conventions table at AGENTS.md line 99 — pre-existing inline content unrelated to §16. The unscoped grep was a false-positive — the §16 extraction succeeded (line 99 example was never in scope to remove), but the test fired anyway.
- **Fix:** Extracted §16 body via `awk '/^## 16\./{inside=1} inside==1{print}' "$A"` to scope both the Appendix A and Appendix B absence checks to actual §16 content. Pipeline shape changed from `! grep -q "$pattern" "$A" || { fail; }` to `echo "$S16" | grep -q "$pattern" && { fail; } || true`.
- **Files modified:** `tests/phase-09.1/test_agents_section_16.sh` (lines 14-23)
- **Commit:** `bdcc2fe`
