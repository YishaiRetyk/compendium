## 1. Executive Summary

Five things the planner needs to know:

1. **The 18 locked decisions are mechanically feasible as stated.** Every line range cited in CONTEXT.md has been verified by direct inspection. §4 is AGENTS.md lines **131–559** (429 lines); §16 is lines **1700–1785** (86 lines). The `schema/AGENTS.template.md` mirror regions for §4 are lines **133–561** (offset +2 from AGENTS.md due to wizard placeholder insertion at line 32) and for §16 are lines **1638–1723** (offset -62 because the template lacks three Phase-9-era inline expansions that were added to AGENTS.md *after* the template was last frozen — see pitfall in §8).

2. **§4 and §16 blocks are byte-identical between `AGENTS.md` and `schema/AGENTS.template.md`.** `diff <(sed -n '131,559p' AGENTS.md) <(sed -n '133,561p' schema/AGENTS.template.md)` returns empty; same for §16 at the offsets above. This means the extraction can be done as identical replacements at different line offsets, and the wizard placeholders at template lines 32, 56, 588–589, 848 are fully outside the extraction zones (verified — Q1 resolved).

3. **The Plan 08-01 canonical render routine is reusable verbatim** — it is a zero-dependency python3 str.replace with leftover-placeholder sanity check, documented in §3 below. After the template is edited (§4 residue + §16 pointer residue) and fixture is regenerated via that exact routine, `cmp -s schema/fixtures/canonical-AGENTS.md schema/AGENTS.template.md` should show only the 4 wizard placeholder substitutions — nothing more, nothing less. The fixture regen is THE single post-extraction mechanical step.

4. **Two CI byte-equality gates are simultaneously in effect; they reinforce rather than fight each other.** (a) `.githooks/pre-commit` enforces `AGENTS.md ≡ CLAUDE.md` via `bin/sync-claude.sh --check` with auto-sync-and-restage. (b) `.github/workflows/setup-parity.yml` enforces `bin/init-wizard.sh --answers-file canonical-answers.yaml --render-to` output ≡ `schema/fixtures/canonical-AGENTS.md`. A single-commit extraction that (i) edits `AGENTS.md`, (ii) edits `schema/AGENTS.template.md` at offset-adjusted line ranges, (iii) regenerates the fixture, (iv) lets pre-commit auto-resync `CLAUDE.md`, passes both gates.

5. **`privacy: cloud_safe` on all 6 §4 worked examples means `schema/examples/*.md` is clean for `bin/release.sh` shipping** — no `^privacy:[[:space:]]*local_only` leaks, no neutrality-denylist tokens (Hinton / Vaswani / deep-learning are pre-vetted neutral per D-07). `schema/` is additionally outside `bin/check-privacy.sh` PUBLIC_PATHS scope, and `docs/` is inside both `check-privacy.sh` and `check-neutrality.sh` scope — the extracted `docs/reference/dataview-queries.md` and `commit-examples.md` contain no frontmatter and no personal terms, so they pass both guards.

**Primary recommendation:** Plan this as a **single-commit extraction** (possibly split across 1–2 waves — Wave-0 test scaffolding, Wave-1 the atomic move). Six schema/examples files + two docs/reference files + AGENTS.md edit + template edit + fixture regen + DR creation + wiki/index.md DR entry + auto-synced CLAUDE.md. Fixture regen is the gate. Everything else is file moves and residue writes.

## 3. Canonical Render Routine (verbatim, from Plan 08-01)

**Source:** `.planning/phases/08-two-track-setup-wizard-manual/08-01-test-harness-and-fixtures-PLAN.md` lines 180–200.

**Purpose:** Regenerate `schema/fixtures/canonical-AGENTS.md` after any edit to `schema/AGENTS.template.md`. Planner should paste this block verbatim into a task's `<action>` section for D-15.

```bash
python3 -c '
import sys
src = open("schema/AGENTS.template.md", encoding="utf-8").read()
subs = {
  "{{AGENT_FILENAME}}":  "CLAUDE.md",
  "{{PRIMARY_DOMAIN}}":  "personal-knowledge",
  "{{DEFAULT_PRIVACY}}": "cloud_safe",
  "{{DECAY_PROFILE}}":   "default",
}
for k, v in subs.items():
  src = src.replace(k, v)
import re
leftover = re.findall(r"\{\{[A-Z_]+\}\}", src)
if leftover:
  sys.exit(f"ERROR: leftover placeholders: {leftover}")
open("schema/fixtures/canonical-AGENTS.md", "w", encoding="utf-8", newline="\n").write(src)
'
```

**Invocation contract:**
- Run from repo root.
- Must be executed AFTER `schema/AGENTS.template.md` has been edited with the §4 and §16 changes.
- Output file: `schema/fixtures/canonical-AGENTS.md`. Overwrites in place.
- Zero-exit on success; non-zero exit with leftover-placeholder list if substitution is incomplete.
- UTF-8, LF line endings, must end with exactly one `\n` (the python3 write with `newline="\n"` preserves the template's terminator verbatim).

**Expected diff shape after a correct run:** `diff schema/AGENTS.template.md schema/fixtures/canonical-AGENTS.md` should show **only** the 4 placeholder substitutions (at template lines 32, 56, 588, 589, 848). If any other diff appears, the template edit is inconsistent with the fixture regen — abort, investigate.

**Alternative regen via wizard** (equivalent output, per Plan 08-01 review concern #13 — both routines MUST agree byte-for-byte):

```bash
bash bin/init-wizard.sh \
    --answers-file schema/fixtures/canonical-answers.yaml \
    --render-to /tmp/wz-regen
cp /tmp/wz-regen/AGENTS.md schema/fixtures/canonical-AGENTS.md
```

The Phase-08 `test_canonical_byte_equality.sh` CI test verifies the two routines agree. Use the python3 str.replace for the extraction task (simpler, no tmpdir, no wizard side-effects on `.wizard-answers.yaml` / decision-record writing).
