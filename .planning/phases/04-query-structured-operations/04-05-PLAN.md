**Question:** "How does prospect theory explain why people make irrational financial decisions?"

Follow all 10 steps of the updated query workflow:

1. **Search:** Run `bash bin/search.sh "prospect theory"` and `bash bin/search.sh "financial"` to find relevant pages. Also read `wiki/index.md` directly.

2. **Shallow read:** Read TL;DR and Key Facts of relevant pages (expect: prospect-theory.md, loss-aversion.md, cognitive-biases.md, decision-making.md, possibly kahneman.md).

3. **Deep read:** Read Detail sections where TL;DR is insufficient to fully answer.

4. **Synthesize:** Compose a cited answer with references to specific wiki pages and provenance markers.

5. **Write-back decision:** Evaluate against the 5 write-back triggers:
   - Does the answer produce a new claim not in the wiki? (probably no — the topic is well-covered)
   - A new connection? (possibly — connecting prospect theory to financial decisions specifically)
   - A reframing? (possibly)
   - A reusable artifact? (no — this is a synthesis of existing content)
   - A correction? (no)
   
   If the answer is primarily a reformulated restatement of existing pages, the correct decision is NO-WRITE-BACK per D-04 ("reformatted restatements of one existing page"). Log the decision.

   If the answer produces genuine novel synthesis (e.g., a connection between prospect theory mechanisms and specific financial behaviors not already articulated), then write back using UPDATE on the appropriate page. Run `bin/validate-op.sh UPDATE <target>` before applying.

6. **Delta compilation:** Check compilation_status on source summary pages found in step 1. All 3 existing sources should have `compilation_status: compiled` (backfilled in Plan 01). Log: "delta_compiled: none".

7-8. **Index + Log:** If any pages were created, update index. Append the query log entry to `wiki/log.md` using the format from section 11.2:

```markdown
## [YYYY-MM-DD] query | How does prospect theory explain irrational financial decisions?

answer: <one-line summary of the synthesized answer>
write_back: <WRITE-BACK: trigger -> action> OR <NO-WRITE-BACK: reformulated restatement of existing pages>
delta_compiled: none
pages_affected: <list or "none">
```

Use today's UTC date. The log entry goes at the bottom of log.md (newest at bottom per AGENTS.md section 12).

9-10. **Commit:** If wiki was modified beyond the log entry, commit with `query(prospect-theory): <summary>`.

IMPORTANT: The write-back decision must be HONEST. If the existing wiki already covers this topic well, the correct answer is NO-WRITE-BACK. Do not force a write-back just to demonstrate the feature. The test validates that the decision logic works, including the "skip" path.
