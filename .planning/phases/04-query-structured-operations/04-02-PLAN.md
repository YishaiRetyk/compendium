**Structure:**

2. Header comment explaining scope: file-system search only, no LLM/API calls

**Arguments (per D-13, D-14, D-15):**

| Argument | Purpose |
|----------|---------|
| `<keyword>` | Positional. Search term for index lookup + full-text grep. |
| `--query "question"` | Query mode: find relevant pages and emit LLM-ready prompt. |
| `--paths-only` | Output file paths only, no TL;DR snippets. |
| `--fulltext` | Also search wiki/ body text (default: index-only). |
| `--help`, `-h` | Show usage. |

**Default mode (per D-13):** Parse `wiki/index.md` for keyword matches (case-insensitive grep on index lines matching `^\- \[\[`). For each match, extract the page path from the wikilink title, find the corresponding file in `wiki/` subdirectories, and extract the TL;DR (first non-empty line after `## TL;DR`). Print: `path/to/page.md -- TL;DR text`.

When `--fulltext` is passed, ALSO run `grep -ril "$keyword" wiki/` (excluding index.md and log.md) and add any results not already found via index. Extract TL;DR for those too.

**`--paths-only` mode (per D-15):** Same search logic but print only file paths, one per line. No TL;DR extraction.

**`--query` mode (per D-14):** Takes a natural language question. Searches index for relevant pages (split question into words, search each). Emits a ready-to-paste LLM prompt:

```
=== Query Prompt ===

Question: <the user's question>

Relevant wiki pages (read in this order, TL;DR first, drill into Detail only if needed):

1. <path> -- <TL;DR>
2. <path> -- <TL;DR>
...

Instructions:
- Read TL;DR and Key Facts sections first (progressive disclosure).
- Read Detail sections only where shallow content is insufficient.
- Cite specific wiki pages and provenance markers in your answer.
- If the answer produces novel synthesis, write it back to the wiki per AGENTS.md section 11.2.
```

**Helper functions:**

`extract_tldr()`:
```bash
extract_tldr() {
    local file="$1"
    sed -n '/^## TL;DR/,/^## /{/^## TL;DR/d;/^## /d;/^$/d;p;}' "$file" | head -1
}
```

`resolve_page_path()` — Given a page title from the index (e.g., "Daniel Kahneman"), find the corresponding file by searching wiki/ subdirectories for files whose frontmatter `title:` or `id:` matches, OR by converting title to kebab-case and checking common paths:
```bash
resolve_page_path() {
    local title="$1"
    local slug
    slug=$(echo "$title" | tr '[:upper:]' '[:lower:]' | sed -E 's/[^a-z0-9]+/-/g; s/^-+|-+$//g')
    # Check each wiki subdirectory
    for dir in wiki/entities wiki/concepts wiki/sources wiki/comparisons wiki/overviews; do
        if [ -f "$dir/$slug.md" ]; then
            echo "$dir/$slug.md"
            return 0
        fi
    done
    # Fallback: grep for matching title in all wiki files
    grep -rl "^title:.*$title" wiki/ 2>/dev/null | head -1
}
```

**Exit codes:** 0 = results found, 1 = error (bad args), 0 = no results (print "No results found" to stdout — not an error).
