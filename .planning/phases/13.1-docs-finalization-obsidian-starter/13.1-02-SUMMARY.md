## Known Dataview-vs-grep Semantic Caveats (flag for the 13.2 live render)

The counts above are STATIC GREP-PROXIES. Two known divergences between grep and live Obsidian Dataview must be confirmed at the live-render step:

1. **`WHERE !privacy`** matches BOTH omitted `privacy` AND present-but-null `privacy` (e.g. `privacy:` with no value), whereas the `grep -L '^privacy:'` proxy only catches OMISSION. All fixtures here either set `privacy: cloud_safe` (a value) or omit the line entirely — none use a bare null `privacy:` — so the proxy and Dataview agree for this set. Expected: 2.
2. **`contains(domains, X)`** requires `domains` to be a YAML LIST. Every fixture uses block-form lists, so the predicate resolves. A scalar `domains: alpha` would silently fail the Dataview predicate (it would not).

`.obsidianignore` is NOT an Obsidian-enforced indexing exclusion (it is a release-manifest / graph-hygiene convention, per Shared Pattern C). The live wiki's `.obsidian/app.json` is `{}`, so `examples/` IS indexed by Dataview today. The DEBT-01 render checklist must instruct the user NOT to add `examples/` to Settings → Files & Links → Excluded files, or the fixtures will return 0 rows.
