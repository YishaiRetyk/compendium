## Shared Patterns

### Shared Pattern A — Template drift-guard (OBSID-01, applies to all 6 `schema/obsidian/` files)

**Source mechanism (RESEARCH Validation Architecture):** the two sets must not drift. After authoring, the field-list (order-sensitive) and section-headers of each Obsidian template must match its canonical sibling modulo the three token substitutions:
```bash
for t in entity concept source-summary comparison overview decision; do
  diff <(grep -E '^[a-z_]+:' schema/templates/$t.md) \
       <(grep -E '^[a-z_]+:' schema/obsidian/$t.md | sed 's/ {{.*}}//')
  diff <(grep '^## ' schema/templates/$t.md) <(grep '^## ' schema/obsidian/$t.md)
done
```
**Apply to:** all 6 templates. The asymmetry (decision-only extra fields) is intentional and the guard must pass WITH it — derive each file from its own canonical sibling, never from a single shared block.

### Shared Pattern B — Reference-doc house style (applies to all `docs/reference/` authored/new files)

**Source:** `docs/reference/three-layer-model.md` + `dataview-queries.md` + `ci.md`. Every reference doc follows:
1. `# Title` (sentence-case, descriptive).
2. Optional `> Reference documentation for <scope>.` blockquote (ci.md/dataview-queries.md) OR a one-paragraph intro (three-layer-model.md).
3. `## TL;DR` (for the heavier docs) or straight into `## ` sections.
4. Optional `> **Source of truth:** ... §<n> wins and this page is the bug.` pointer when reproducing CLAUDE.md content (ci.md pattern).
5. `## See also` footer with relative links to `AGENTS.md`, `../README.md`, sibling docs.
**Apply to:** `obsidian-starter.md`, `schema-tour.md`, `privacy-model.md`, `examples.md`, `agent-parity.md`.

### Shared Pattern C — `.obsidianignore` doc correction (D-05 tension, applies to `examples.md`)

**Source:** RESEARCH Pitfall 1. The stub's claim that `.obsidianignore` "hides examples from indexing" is **factually wrong** — Obsidian has no native `.obsidianignore` support; the live `.obsidian/app.json` is `{}` so `examples/` IS indexed by Dataview today. Correct the description to: `.obsidianignore` is a **release-manifest + graph-hygiene convention** (consumed by `bin/release.sh` + docs), NOT an Obsidian-enforced indexing exclusion. The real exclusion mechanism is Settings → Files & Links → Excluded files (`app.json` `userIgnoreFilters`). The DEBT-01 render checklist must tell the user NOT to add `examples/` to Excluded files (fixtures must stay indexed for Dataview).

### Shared Pattern D — Neutrality gate (D-12, applies to ALL docs + templates)
