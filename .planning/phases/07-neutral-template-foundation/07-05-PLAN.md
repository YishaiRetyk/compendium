**`.neutrality-denylist.txt` format:**
- One term/phrase per line.
- `#` starts a comment (skipped).
- Blank lines skipped.
- Terms are matched case-insensitively as fixed strings (no regex).

**`bin/check-neutrality.sh --suggest-denylist` DETERMINISTIC contract (REVIEWS.md HIGH #3):**
The suggest mode MUST document and restrict itself to these input sources:

1. Wiki pages with `privacy: local_only` frontmatter (if any remain in the scanned tree).
2. `.planning/notes/**/*.md` (creator personal notes, gitignored from public releases).
3. Git history of known-deleted `local_only` files: `git log --all --source --pretty=format: -p -- <paths>` where `<paths>` are `.planning/notes/**`, `wiki/overviews/personal-decision-patterns.md`, `wiki/sources/src-2026-04-10-personal-decision-journal.md`.
4. File names in `.gitignore` that look creator-specific (personal project names, family references) — optional fourth source, off by default; enabled with `--include-gitignore`.

Extraction rule (deterministic, same inputs → same output):
- Tokenize on word boundaries: `\b[A-Za-z][A-Za-z0-9-]{2,}\b` (length ≥ 3, lowercase-normalized).
- Filter against a fixed stopword list (~50 common English words, embedded in the script — documented in the help output and printed with `--show-stopwords`).
- Preserve multi-word phrases when they appear in page slugs or frontmatter titles (e.g., "personal-decision-patterns" → kept as-is, not split on hyphens for hyphenated compound terms).
- Output is sorted lexicographically and grouped by source with `# source: <path>` banners.
- Running the command twice back-to-back MUST produce byte-identical output (deterministic).

**`bin/release.sh` contract (D-04, REVIEWS.md HIGH #1 — ALLOWLIST-BASED FRESH-TEMP-DIR STAGING):**

The script MUST NOT use `git worktree add` + `rm -rf .git && git init` (that was the original unsafe design). Instead:

1. `--remote <url>` required (D-02: no baked-in identity).
2. `--tag <tag>` optional (default `v1.1`).
3. `--dry-run` default: print allowlist, print file set that would be copied (with explicit `INCLUDES:` and `EXCLUDES:` prefix lines for test assertions), print commit plan, print refs to push; no mutation.
4. `--apply` + interactive y/N: execute staging + push.
5. `RELEASE_EMAIL` env var override, default `release@example.invalid` (reserved `.invalid` TLD per RFC 2606, unambiguously non-routable — REVIEWS.md HIGH #5).
6. Staging algorithm (ALLOWLIST — REVIEWS.md HIGH #1):
   a. Create fresh empty directory OUTSIDE the repo: `STAGE=$(mktemp -d -t gsd-release-XXXXXX)`.
   b. Install trap: `trap 'rm -rf "$STAGE"' EXIT INT TERM ERR`.
   c. Copy ONLY files matching the explicit allowlist (see below) from the current repo into `$STAGE`. Use `cp --parents` or `rsync --relative` to preserve directory structure; NEVER use `cp -r .` (that would copy everything).
   d. Inside `$STAGE`: `git init --initial-branch=main`, configure `user.email="$RELEASE_EMAIL"`, `user.name="release"`, `git add .`, single commit with message `${TAG} release`.
   e. Run `bin/check-neutrality.sh --root "$STAGE" --denylist "$STAGE/.neutrality-denylist.txt"` against the staged dir (pre-flight gate). Hard-fail if it trips.
   f. Run `bash bin/sync-claude.sh --check` inside `$STAGE` for redundant byte-equality check.
   g. `git tag "$TAG"` in `$STAGE`.
   h. `git push "$REMOTE" HEAD:main` and `git push "$REMOTE" "$TAG"` from `$STAGE`.
7. Explicit allowlist (the ONLY files/globs that may appear in the published repo):

    ```bash
    # bin/check-neutrality.sh -- NEUT-06 + NEUT-08 gate.
    # Greps public control-plane paths against a denylist (Kahneman + personal terms).
    # Exits 0 on clean; 1 on script failure; 2 on denylist match.

    # --suggest-denylist mode is DETERMINISTIC (REVIEWS.md HIGH #3):
    #   Input sources (in order):
    #     1. wiki/ pages with `privacy: local_only` frontmatter under $ROOT
    #     2. .planning/notes/**/*.md under $ROOT (creator personal notes)
    #     3. Git history of known-deleted local_only paths via `git log --all -p -- <paths>`
    #     4. (Optional, with --include-gitignore) creator-specific patterns in .gitignore
    #   Extraction rule:
    #     - Tokenize on word boundaries: \b[A-Za-z][A-Za-z0-9-]{2,}\b (length >=3)
    #     - Lowercase-normalize
    #     - Filter against embedded stopword list (see --show-stopwords)
    #     - Preserve hyphenated slugs as single tokens
    #     - Sort lexicographically within each source group
    set -euo pipefail

    ROOT="${PWD}"
    DENYLIST=".neutrality-denylist.txt"
    SUGGEST=0
    INCLUDE_GITIGNORE=0
    SHOW_STOPWORDS=0
    FORMAT="text"

    usage() { cat <<'EOF'
    Usage: bin/check-neutrality.sh [OPTIONS]
    Options:
      --root DIR              Scan root (default: PWD)
      --denylist FILE         Denylist file (default: .neutrality-denylist.txt under root)
      --format text|json      Output format (default: text)
      --suggest-denylist      Emit candidate terms (see sources + rule in source comment); no denylist required
      --include-gitignore     In suggest mode, also scan .gitignore for creator-specific patterns (default: off)
      --show-stopwords        Print the embedded stopword list and exit 0

    Suggest-mode input sources (deterministic):
      1. wiki/**/*.md with `privacy: local_only`
      2. .planning/notes/**/*.md
      3. git log --all -p -- <known-deleted local_only paths>
      4. .gitignore creator-specific patterns (only with --include-gitignore)

    Extraction rule:
      - Token: \b[A-Za-z][A-Za-z0-9-]{2,}\b, lowercase-normalized, length >= 3
      - Filter against embedded stopword list
      - Preserve hyphenated slugs as single tokens
      - Sort lexicographically within each source group

    Exit: 0 clean, 1 script failure, 2 denylist hit
    EOF
    }

    # flag parse ...

    PUBLIC_PATHS=(AGENTS.md CLAUDE.md README.md PRIVACY.md docs .github wiki bin)
    ```
