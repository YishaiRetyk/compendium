**Step B — Add the shared markdown-masking helper (review HIGH #2, #3 — NET-NEW, load-bearing):**

Define a module-level helper near the other regexes (around line 386, after WIKILINK_RE) inside the
Python heredoc. It replaces the spans that must NEVER be scanned-as-links or rewritten with
length-preserving filler so character OFFSETS are preserved (this matters for the positional --fix
in Step C — the masked string and the real content must be index-aligned). Mask, in order:
1. YAML frontmatter (the leading `---\n ... \n---` block, only if the file STARTS with `---`).
2. Fenced code blocks (```` ```...``` ```` and `~~~...~~~`).
3. HTML comments (`<!-- ... -->`), including multi-line — this covers FORBIDDEN PATTERNS blocks.
4. Inline code spans (`` `...` ``).

```python
_FENCE_RE   = re.compile(r'(^|\n)(```|~~~)[^\n]*\n.*?\n\2[ \t]*(?=\n|$)', re.DOTALL)
_HTMLCOM_RE = re.compile(r'<!--.*?-->', re.DOTALL)
_INLINE_RE  = re.compile(r'`[^`\n]*`')
_FM_RE      = re.compile(r'\A---\n.*?\n---\n', re.DOTALL)

def mask_markdown(text):
    """Return a length-preserving copy of `text` with YAML frontmatter, fenced code,
    HTML comments, and inline code replaced by spaces (newlines kept). Offsets are
    preserved so positional --fix can map masked-match spans back to the real content.
    Order matters: frontmatter and fences first (they may contain `<!--` / backticks),
    then HTML comments, then inline code."""
    def _blank(m):
        return ''.join('\n' if c == '\n' else ' ' for c in m.group(0))
    masked = _FM_RE.sub(_blank, text)
    masked = _FENCE_RE.sub(_blank, masked)
    masked = _HTMLCOM_RE.sub(_blank, masked)
    masked = _INLINE_RE.sub(_blank, masked)
    return masked
```
(The executor MAY refine the regexes, but the contract is fixed: the four span types above are
neutralised, offsets are preserved, and the SAME masked string is used by both the scan and the
--fix rewrite. A literal `[[id|Title]]` inside any masked span is invisible to linkres.)

FRONTMATTER PRESERVATION (review HIGH #2 / cycle-1 #2 — load-bearing): `_FM_RE` blanks the leading
`---\n...\n---\n` frontmatter block so it is invisible to the scan, but because masking is
LENGTH-PRESERVING and the linkres worklist carries the FULL file text (Step C reads `abs_path`, not
the parsed `body`), the positional --fix splices rewrites into the full `raw` string. No bare-link
span can fall inside the masked frontmatter region, so frontmatter is written back byte-for-byte
unchanged. This is precisely why the worklist MUST read the full file and not `body`: writing a
body-only string back to the full path would silently drop the frontmatter (the cycle-1 #2 defect).

        if fm.get('title'):

                            f"(LINK-04: bare form not allowed even for red links)")

                            f"bare link [[{bare}]] matches multiple pages "
