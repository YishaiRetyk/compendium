## Sections to write:

**## 1. The 5 Dimensions**
A prose paragraph then a table. The 5 dimensions are:
1. Acquisition — how the source is obtained (downloaded, recorded, scraped, generated)
2. Locator — what locator syntax addresses claims (#p, #sec:, #t, #r, none)
3. Extraction granularity — atomic claims vs paragraph clusters vs bulk-copy
4. Drift — whether the source can change post-ingest (static = no, live = yes, published-immutable = no after publish)
5. Epistemic default — the default `epistemic_status` to assign pages whose claims are predominantly this source type

**## 2. Primary vs Secondary Axis**
- Primary sources: `support_type: direct` — the wiki claim traces to the source material itself.
- Secondary sources: `support_type: derived` — the wiki claim traces to a synthesis or aggregation of primary material; the original primary sources are one step removed.
- Decision rule: "A new `source_type` is justified only if it changes at least one of the 5 dimensions relative to all existing types. If all 5 dimensions match an existing type, the candidate is documented as a sub-case — a convention note on an existing type — NOT a new enum value."

**## 3. Retro-fit Table (all 7 types)**
A markdown table mapping all 7 source types across the 5 dimensions. Columns: Type | Axis | Acquisition | Locator | Extraction Granularity | Drift | Epistemic Default. Use ONLY these values in the Type column (the 6 existing enum values plus research-report as the 7th):
- article — primary — downloaded/copy-paste — #sec:, #para — paragraph clusters or atomic — static — sourced
- paper — primary — downloaded/copy-paste — #p, #sec:, #para — atomic claims — static — sourced
- transcript — primary — recorded or downloaded — #t<start>-<end> — paragraph clusters — static after recording — sourced
- journal — primary — written by author — #sec:, #para — paragraph clusters — static after writing — mixed
- data — primary — downloaded — #p or none — bulk-copy or cited stats — static — sourced
- image — primary — downloaded/captured — #img<n> — described content — static — sourced
- research-report — secondary — AI-generated or third-party aggregated — #r<n> for bibliography; #sec:, #para for body — atomic claims, support_type: derived only — static after generation — mixed

**## 4. Evaluated Candidates Sub-case Registry**
A markdown table for evaluating new type candidates. Per D-04, Phases 20 and 21 append rows here. Columns: Candidate | Verdict | Dimensions That Change | Convention Doc | Notes.

**## 5. research-report — Worked Secondary Instance**
Full convention for the research-report type (makes it the "worked instance" of EXT-03):
- Classification: Pass 0 assigns `source_type: research-report` when the source is an AI-synthesized report (Claude / ChatGPT / Perplexity / similar) or a third-party aggregated research artifact with its own bibliography.
- Provenance: ALL claims use `support_type: derived` (NEVER `direct` — lint enforces this as an error). Locator: `#r<n>` for bibliography-specific claims (nth bullet in the bibliography section); `#sec:` or `#para` for body claims.
- Citation registry: The source summary page's `## References` block captures the bibliography as an addressable registry. Format: `- r<n>:: [<Title>](<URL>) — accessed <date> — status: registry`.
- Epistemic default: `mixed` for body conclusions; `tentative` for claims derived solely from bibliography entries without further verification.
- Promotion path (Model C): When a citation-registry entry earns a claim, the human acquires the primary source and ingests it normally. The earning claim is re-pointed: `[prov:<report-id>#r<n>|derived]` → `[prov:<new-source-id>#<locator>|direct]` (an UPDATE op). The registry entry is marked `promoted → <new-source-id>`.
- Audit priority: Research-report claims are tier-5 audit targets (`--select derived-report`); they carry a lower epistemic default and the faithfulness audit should sample them first.
- Anti-laundering note: Two reports citing each other can manufacture false consensus. The `derived` support type, lower epistemic default, and audit priority are the mechanical defenses. Never flatten a research-report's synthesis into `direct` claims — that erases the secondary-source signal.

**## 6. Ingest Checklist for research-report**
Brief ordered checklist:
1. Save the raw report with bibliography intact to `sources/` (raw source is immutable — never strip the bibliography).
2. Assign `source_type: research-report` in the source summary frontmatter.
3. Add `## References` block to the source summary with `r<n>::` keyed entries for each bibliography entry.
4. Extract claims with `support_type: derived` and `#r<n>` or `#sec:`/`#para` locators.
5. Set `epistemic_status: mixed` on the source summary and dependent pages by default.
