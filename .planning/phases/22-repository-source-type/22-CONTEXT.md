# Phase 22 Context — Repository Source Type

**Planned:** 2026-07-03 (autonomous session; design decisions made in lieu of /gsd-discuss-phase, each with rationale so they are reviewable)
**Requirements:** REPO-01..06
**Design inputs:** `.planning/seeds/primary-source-type-extensions.md` (Candidate A — the seed's 10 open questions are answered below), `schema/reference/source-types.md` (the contract), Phase 20/21 sub-case precedents (pdf-ingestion.md / video-ingestion.md structure).

## Decisions (D-numbers referenced by plans and the DR)

- **D-01 — New primary type, not a sub-case.** Walking the contract: **Locator changes unconditionally** (`#path:`/`#commit:` do not exist — unlike video, where `#t` already existed), **Drift changes unconditionally** (`live` upstream — the FIRST type whose drift value is not static/published-immutable; every existing type never changes post-ingest), **Acquisition changes unconditionally** (snapshot from a live VCS), **Epistemic Default changes structurally** (within-source claim-class split, new to the system). 4 of 5 dimensions → comfortably past the ≥1 bar. Answers seed Q1: a dedicated type buys the locator grammar, the SHA-drift hook Phase 23 consumes, and the epistemic split — none expressible as a convention note on an existing type.
- **D-02 — Minimal locator grammar:** `#path:<file>` , `#path:<file>:L<n>` , `#path:<file>:L<n>-L<m>` , and `#commit:<sha>` (7-40 hex chars). `#issue:`/`#pr:` DEFERRED (tracked as IPR in REQUIREMENTS.md Future) — the snapshot does not capture them, so they would be unresolvable-by-construction. `#sec:` keeps working for README/doc prose (the snapshot is markdown). Answers seed Q2.
- **D-03 — Raw-source scope: curated snapshot bundle, NOT a clone.** Bundle dir with `source.md` containing: metadata header section (repo, SHA, branch, license, language, retrieved date), curated README/docs content, and an **`## Excerpts` registry** — code excerpts the curator quotes, each under a `### <path>:L<n>-L<m>` heading with a fenced block. Mirrors the research-report `## References` registry pattern: the registry is what makes the new locator **audit-resolvable offline**. Answers seed Q3.
- **D-04 — `#path:` resolves against the Excerpts registry.** `bin/audit-claims.sh` matches a `#path:` locator to a `### <path>[:L...]` excerpt heading (exact path match; line ranges resolve when contained in an excerpt's range). No excerpt → `insufficient-locator` (honest degradation, same as `#p` without page markers / `#r` without bibliography). The registry convention nudges authors: if you anchor a claim to code, quote the code.
- **D-05 — `#commit:<sha>` resolves against the snapshot metadata.** Valid only for the snapshot's own `commit_sha` (prefix match ≥7 chars) → resolves to the metadata section passage. Any other SHA → `insufficient-locator`. Rationale: the snapshot documents exactly one commit; claims about other commits have no local evidence.
- **D-06 — Frontmatter:** required on repository sources: `repo_url`, `commit_sha` (full 40-hex), `default_branch`; recommended: `license`, `primary_language`, `stars_at_ingest` (omit when unknown — never empty strings). Flat snake_case fields (Dataview-queryable, per the D-06 Phase-20 precedent). `knowledge_domain: software` (180-day decay). Lint REQUIRES `repo_url` + `commit_sha` + `default_branch` conditionally on `source_type: repository` (D-07-analog of the PDF original_asset trigger — here the type IS the mechanical signal, so unlike video there is no guessing problem). Answers seed Q4 partially (drift fields), Q5 via D-08.
- **D-07 — Drift stance (consumed by Phase 23):** upstream is `live`; the committed snapshot is immutable and claims remain faithful to it. Drift = upstream default-branch HEAD ≠ `commit_sha` (detection: `git ls-remote`, no clone) or repo unreachable (rot). Surfaced review-only; re-snapshot is a NEW ingest (the old source stays, superseded normally). No drift machinery ships in Phase 22 — only the fields it needs.
- **D-08 — Within-source epistemic split** (primary source; `support_type: direct` throughout — extraction is not derivation, same principle as PDF/video): code/benchmark claims anchored `#path:`/`#commit:` → `sourced`; self-descriptive capability claims from README marketing prose ("fast", "production-ready") → claim-level `[epistemic:: tentative]` hedge mandated even on `sourced` pages; benchmark numbers → cite the number verbatim. Page default `sourced` for code-heavy summaries, `mixed` when README-claims dominate. Transcription-risk precedent applies: risk lives in epistemic status, never in support type.
- **D-09 — Thin glue `bin/repo-snapshot.sh`:** shallow-clones to a temp dir, harvests metadata (HEAD SHA, default branch, license file, dominant language by extension count), and emits a snapshot `source.md` skeleton (metadata section + README body + empty Excerpts scaffold) to stdout or a bundle dir. Curation (choosing docs/excerpts) stays human/agent work — the script does the mechanical part only (Phase 10 mechanical-vs-judgment boundary). Template-public: placeholders only in its help text.
- **D-10 — Validation target: `gsd-build/get-shit-done`** (the GSD framework repo). Rationale: the wiki already has an entity page (`wiki-cloud/entities/gsd.md`) whose claims currently trace to a research-report (derived) — a repository ingest UPGRADES an existing knowledge cluster with primary evidence, demonstrating the promotion story (derived report claim → direct repo claim) end-to-end. Public repo → cloud tier. (Fallback if unreachable: `github/spec-kit`, same reasoning via the spec-kit entity.)
- **D-11 — Resolver dispatch order:** `#path:` and `#commit:` branches MUST be checked before the existing `#p`/`#para` branches in `resolve_locator` (shared `#p` prefix would otherwise swallow `#path:` into the page-range branch and return insufficient). Regression test required.
- **D-12 — Pass-0 wording:** repository is a first-class enum value at classify time (unlike pdf/video which classify to parent types) — the ingest.md bullet says so explicitly to prevent agents pattern-matching it into the sub-case frame.
