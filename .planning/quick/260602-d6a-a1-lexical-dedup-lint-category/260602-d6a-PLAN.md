## Task 1 — Implement the `duplicate` check in bin/lint.sh

**Files:** `bin/lint.sh`

**Action:**
- Add a new `if should_run('duplicate'):` block inside the existing single python3 block,
  placed after the `gap` check and before the `drift` check.
- Walk active wiki pages (reuse the page inventory the orphan/crossref checks already build:
  `resolution_map`, page id/title/aliases, and the inbound-wikilink graph). Exclude
  `EXCLUDE_DIRS`/`examples/`, pages with `example: true`, and pages whose `status` is
  `archived` or `superseded`.
- Group candidate pages by their frontmatter `type`. For each **same-type** unordered pair:
  - **Candidate iff EITHER**
    - one page's title OR any alias contains the other's title/alias as a case-insensitive
      substring (only when the contained string length > 5), **OR**
    - `levenshtein(title_a, title_b) < 3` for titles longer than 5 chars.
  - **Survivor** = the page with MORE inbound wikilinks (reuse the link graph; tie → keep
    lexicographically-first id as survivor, deterministic).
  - Emit ONE finding per pair (dedup on a sorted `(id_a, id_b)` pair-key):
    `add_finding('warning', 'duplicate', <loser_path>,
      f'possible duplicate of "{survivor_title}" ({survivor_id}); same type={t}; consider MERGE (§9). '
      f'Survivor by inbound-link count ({n_loser} vs {n_survivor}).')`
- Implement a small pure-stdlib Levenshtein helper (no new imports beyond stdlib).
- **Report-only**: no `--fix` behavior, never mutates pages, never auto-merges.

**Verify:** `bash bin/lint.sh --category duplicate` exits 0 and prints `duplicate`
findings (or none) without error on the live wiki. Expect at least the known pair
`entities/anthropic.md` vs `entities/anthropic-financial-services.md` to surface (a known
false positive — acceptable, report-only).

**Done:** check runs, same-type-only, report-only, deterministic survivor + pair-dedup.
